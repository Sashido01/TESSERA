# First Immutable Release publication (0.1.0)

[Русский — оригинал](IMMUTABLE_RELEASE.md) | **English — translation**

Owner approved on 26 November 2026. Do not publish until G01–G12 are closed in applicable sequence: pre-release acceptance and verified sources before tag, exact main CI, ZIP build/verification, draft, publication and independent verification after tag. Never claim RELEASED before final verification. Plan status NOT_RUN.

1. Settings → General → Releases: enable release immutability. In trusted owner terminal check `gh api --include -H 'X-GitHub-Api-Version: 2026-03-10' repos/Sashido01/TESSERA/immutable-releases`: HTTP 200 and JSON `enabled: true` confirm enabled. Authorized PUT of the same endpoint returns HTTP 204; subsequent GET is mandatory. 404, permissions/network error or unsupported endpoint does not confirm enabled. Never weaken Rulesets. [Settings](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/establish-provenance-and-integrity/prevent-release-changes).
2. After exact v0.1.0 and main CI verified, dispatch `gh workflow run build-attested-catalog.yml --repo Sashido01/TESSERA --ref v0.1.0`. Identify run by workflow_dispatch, tag, SHA, attempt and success. Download its specific artifact `tessera-catalog-v0.1.0` into a fresh private empty directory. Check manifest, ZIP size, SHA-256 and reproducibility per [Trusted Build](TRUSTED_BUILD.en.md).
3. Run `gh attestation verify <zip> --repo Sashido01/TESSERA --source-ref refs/tags/v0.1.0 --source-digest <exact-commit> --signer-workflow Sashido01/TESSERA/.github/workflows/build-attested-catalog.yml --deny-self-hosted-runners`. Record actual result/digest. Never use placeholder as SHA. Verify no existing Release for tag; if one exists, stop and inspect, never overwrite.
4. Create only draft from existing tag: `gh release create v0.1.0 <verified-zip> --repo Sashido01/TESSERA --verify-tag --draft --title "TESSERA 0.1.0" --notes-file <reviewed-bilingual-notes>`. Attach every approved asset before publishing, never use --clobber. Verify tagName, isDraft, exact assets, sizes and bytes downloaded from draft into new directory. Compare SHA-256 to verified ZIP and repeat attestation verify. Recheck immutability setting. Do not publish with missing mandatory results.
5. Only after independent draft checks and readiness, publish using `gh release edit v0.1.0 --repo Sashido01/TESSERA --draft=false`. After publication check `gh release verify v0.1.0 --repo Sashido01/TESSERA` and `gh release verify-asset v0.1.0 <zip> --repo Sashido01/TESSERA`; download published ZIP and repeat SHA-256/workflow attestation. Verify published Release, immutable=true metadata, exact Git tag and CI. Release attestation and Actions workflow attestation are separate. Dynamic Source code ZIP/TAR are not covered by verify-asset. Never modify immutable assets/tag; defect requires a new version by policy.

Command documentation: [gh release create](https://cli.github.com/manual/gh_release_create), [gh release verify](https://cli.github.com/manual/gh_release_verify), [gh release verify-asset](https://cli.github.com/manual/gh_release_verify-asset), [gh attestation verify](https://cli.github.com/manual/gh_attestation_verify).
