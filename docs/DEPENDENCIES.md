# Зависимости и ограничения TESSERA

[**Русский — оригинал**](DEPENDENCIES.md) | [English — перевод](DEPENDENCIES.en.md)

## Утверждённая политика

Документ фиксирует решение владельца от 23.11.2026. Русский текст является первоисточником. Документ описывает **допустимые средства**, но не доказывает, что они уже установлены или испытаны в локальном окружении.

## Разрешённая основа

| Средство | Статус | Назначение |
| --- | --- | --- |
| Git | Обязателен для Git-операций | Коммиты, история и аннотированные теги |
| Python 3, стандартная библиотека | Основа собственных инструментов | Калькулятор версий, проверки, минимальный офлайн-установщик |
| Официальный GitHub CLI (`gh skill`) | Основной планируемый путь распространения после испытаний | Обнаружение, установка, pin по SHA/тегу, обновления |
| Agent Skills | Стандарт публикации навыков | Переносимый SKILL.md и структура каталога |
| Официальный `skills-ref` | Запланирован как эталонный валидатор | Проверка общих требований стандарта |
| NVIDIA SkillEvaluator **Tier 1** | Только после оценки в изоляции | Бесплатные базовые статические проверки; не runtime |
| Собственные адаптеры Codex/Harness/Claude/Hermes | Запланированы | Вызов общего ядра и проверка выполнения |

Утверждение «бесплатный Tier 1» относится к отсутствию обязательных платных AI API: CI и инфраструктура могут иметь собственные операционные ограничения. Перед подключением нужны проверенные команды, версии и оценка фактических затрат.

## Явно исключённые решения

- **Vercel Skills CLI (`npx skills`) не используется вообще** — не основная или резервная установка, не зависимость, не автоматические обновления и не инструмент CI. Не добавлять его обратно без отдельного нового решения владельца.
- **NVIDIA SkillEvaluator Tier 2 и Tier 3 не используются.** Не запускать их, не настраивать и не вводить как будущие обязательные этапы.
- Платные AI API, внешние эмбеддинги и облачные LLM-сервисы **не должны быть обязательны** для установки, проверки, выпуска и использования навыков.
- Не включать сторонние расширения агентных систем автоматически. Сначала аудит источника, лицензии, версии, разрешений и фактических потребностей.
- Не создавать отдельные ядра управления версиями для каждого агента: одно независимое ядро TESSERA и небольшие адаптеры.
- Не дублировать нативные функции GitHub CLI своим менеджером без подтверждённой технической причины.

## Порядок исследования новых инструментов

1. Проверить официальный источник и актуальную версию.
2. Проверить лицензию и исполняемые зависимости.
3. Подтвердить, что инструмент работает без платных ключей и выполняет именно нужную функцию.
4. Испытать в изолированном окружении, без доступа к пользовательским секретам и файлам других проектов.
5. Замерить время, объём зависимостей, результат и побочные эффекты.
6. Установить ограниченные версии и добавить воспроизводимые тесты/CI.
7. Документировать результат в русском оригинале и английском переводе; отметить NOT_VERIFIED, если испытания не проведены.

## Роль офлайн-установщика

Существующий Python `install.py` сохраняется как минимальная опция для офлайн-среды и специальных профилей. Он не должен конкурировать с `gh skill` как универсальный менеджер пакетов. Любое копирование в проект требует явного согласия и не может без предупреждения перезаписать установленный навык.
