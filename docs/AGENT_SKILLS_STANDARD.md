# T11.01 — проверка Agent Skills по эталонной реализации

[**Русский — оригинал**](AGENT_SKILLS_STANDARD.md) | [English — перевод](AGENT_SKILLS_STANDARD.en.md)

## Цель и границы

TESSERA использует общедоступную [спецификацию Agent Skills](https://agentskills.io/specification). Наряду с собственным `tools/validate_skills.py` на каждый Pull Request и push в `main` выполняется отдельный `skills-ref validate` из исходного [agentskills/agentskills](https://github.com/agentskills/agentskills).

**Важно:** разработчики официальной reference-библиотеки прямо указывают, что `skills-ref` предназначен для демонстрации и не является production-решением. Поэтому проверки TESSERA для приватности, версий, тегов, двух языков и целостности не заменяются reference-валидатором. Даже успешная проверка обоими валидаторами не доказывает активацию навыка в Codex, Harness, Claude Code или Hermes.

## Фиксация источников

- Исходный репозиторий: `agentskills/agentskills`, **полный commit SHA** `83021e2be457a9b6679148719c1f6074f0ad975e`. Это выбранный и проверенный на момент T11.01 снимок, а не «всегда актуальный main».
- Проверяется `git rev-parse HEAD` второго checkout. Переключения на произвольный `main` и установки пакета `skills-ref` из PyPI нет.
- Зависимости из upstream `skills-ref/uv.lock` закреплены версиями и хешами wheel в `tools/skills-ref-requirements.txt`. При несоответствии хешей или отсутствии файла CI даёт FAIL.
- Внешний исходник загружается **после** собственного пакета и модульных тестов TESSERA, так как второй checkout создаёт временную незарегистрированную папку в рабочем каталоге. Временная папка не коммитится и не входит в ZIP.
- У CI нет права Git-записи в задаче `validate`, оба checkout не сохраняют credentials. Никакие исполняемые скрипты навыков не запускаются.

Для непосредственного запуска после локальной подготовки pinned upstream checkout и зависимости в отдельном доверенном Python-окружении:

~~~bash
python tools/check_reference_skills.py --repo . --reference-src .external/agentskills/skills-ref/src
~~~

Wrapper передаёт каталоги навыков в `python -P -m skills_ref.cli validate`, с ограничением времени 30 секунд на навык и фиксированным `PYTHONPATH` к исходникам checkout. Отказ при отсутствии CLI, ошибке парсинга, плохом имени каталога, symlink, timeout или некорректном ответе. Он не выполняет сетевых запросов и не публикует GitHub Release.

**Обратите внимание:** только успешный GitHub Actions CI после слияния доказывает, что pinned reference-validator реально был запущен в Linux. Статические тесты wrapper и инструкции сами по себе такого доказательства не дают.

## Отдельно: публикационная пригодность

Официальная команда `gh skill publish --dry-run` действительно предусмотрена GitHub CLI. Она валидирует навыки и не создаёт GitHub Release, но остаётся preview. В T11.01 эта команда **не запускалась**; её реальная проверка с точной установленной версией `gh`, побочными эффектами и поведением монорепозитория является самостоятельной задачей T11.02/T10.

Нельзя запускать `gh skill publish` без `--dry-run` для автоматической проверки: такая команда может создавать релиз, менять topic и запрашивать действия пользователя.

## Критерии

T11.01 — COMPLETE только если обязательный CI с upstream checkout и эталонным валидатором реально завершился SUCCESS. T11 в целом остаётся PARTIAL до T11.02 и проверки поведения в реальных агентских клиентах. Отдельный контроль установки — T03/T05.
