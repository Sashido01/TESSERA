# T12.03.02 — безопасная проверка GitHub CI

[**Русский — оригинал**](RELEASE_CI_SECURITY.md) | [English — перевод](RELEASE_CI_SECURITY.en.md)

## Причина

Bandit B310 в core/release_ci.py: прежний код допускал HTTP-перенаправление внутри urllib.request.urlopen, а проверял конечный hostname уже после запроса. Запрос на неожиданный хост мог быть отправлен до отказа. Это недостаток ограничения сетевого назначения; доказанного инцидента утечки нет.

## Изменение

Разрешены только точные HTTPS адреса api.github.com/repos/OWNER/REPO/actions/runs/ID и .../jobs?per_page=100. Валидация пути, идентификаторов и параметров до открытия соединения. NoAPIRedirect запрещает переход по 301/302/303/307/308 до следующего запроса, включая другой путь того же хоста. Проверяется точный URL ответа до чтения тела. Таймаут 15 секунд и лимит 2 MiB сохранены. Токены и новые зависимости не добавляются.

## Приёмка

Четыре регрессионных теста: запрет перенаправлений, отказ до сетевого вызова на неверных URL, корректный opener/timeout, изменённый URL ответа. Не заменяют реальную сетевую проверку и не утверждают сетевую изоляцию процесса. Правило Bandit не подавляется. B310 может остаться как эвристическое предупреждение; оцениваются реализованное ограничение и тесты, а не число замечаний. Необходим реальный CI; другие находки Bandit открыты.

[CI 45376483433](https://github.com/Sashido01/TESSERA/actions/runs/45376483433) PASS: 493+19 тестов, четыре новых регрессии PASS, Bandit B310 отсутствует в повторном обзоре; 110 замечаний (без HIGH), правила не подавлялись. T12.03.02 COMPLETE в пределах реализованной защиты и CI; реальное сетевое выполнение отдельно NOT_VERIFIED.

## Исправление регрессии до слияния

Перед слиянием обнаружена регрессия общей функции get_public_json: первоначальный строгий перечень адресов блокировал уже существующий вызов GitHub Release metadata. Добавлен только канонический маршрут /releases/tags/vMAJOR.MINOR.PATCH и одно пространство имён с %2F; произвольное URL-кодирование, дополнительные пути и параметры запрещены. Три регрессии проверяют действительный путь вызова verify_github_publication через общий транспорт (обычный и namespaced тег), отклонение изменённого URL ответа и недопустимые маршруты. Сетевой слой подменяется, а валидация и обработка ответа реальные. Исторический PASS не охватывал эту ошибку; новая приёмка обязательна.
