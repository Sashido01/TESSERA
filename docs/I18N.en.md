# TESSERA language policy

[Русский — оригинал](I18N.md) | **English — translation**

## Core rule

**All public documentation is written and reviewed in Russian first.** The English copy is a complete translation, not a shortened summary. If the versions conflict, the Russian original governs; the inconsistency must be fixed.

## File naming

- `README.md` is the canonical Russian file; `README.en.md` is its English translation.
- The same rule applies to `AGENTS.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, and `docs/*.md`.
- Each skill has Russian `skills/<slug>/README.md` and English `README.en.md`.
- The Agent Skills entry point is **only** `skills/<slug>/SKILL.md`, in Russian. The instruction translation lives at `skills/<slug>/references/SKILL.en.md`. Do not create a second discovery entry point under a translated skill directory.
- Other Russian reference Markdown files under `references/` receive paired `*.en.md` files.
- `LICENSE` and machine-readable or executable files (Python, CI, GitHub YAML templates) follow their ecosystem's requirements; executable files do not need translated duplicates.
- GitHub issue and PR templates may be bilingual with Russian first; separate translations are not required for GitHub to function. Public guides need full English copies.

## Updating documentation

1. Change and review the Russian original first.
2. Update its complete English translation in the **same change**: preserve meaning, limitations, commands, paths, links, versions, and status labels.
3. Add a Russian/English switch at the top of each document.
4. Keep technical identifiers, commands, paths, filenames, and status codes unchanged. Never publish private local paths.
5. Write commits, annotated tag descriptions, release notes, and main reports in clear Russian. An optional English section may follow the Russian text.
6. Run `python tools/check_translations.py` and the other tests. Automated checks confirm file coverage; a human reviewer must confirm semantic accuracy.

## Limits of automation

CI can detect missing translation pairs, orphaned English documents, and missing language links. It **cannot prove** translation accuracy or freshness. Reviewers must check meaning.
