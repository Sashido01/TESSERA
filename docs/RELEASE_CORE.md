# Release Core — инспектор Git-доказательств (T09.01)

[**Русский — оригинал**](RELEASE_CORE.md) | [English — перевод](RELEASE_CORE.en.md)

## Назначение

`core/release_inspect.py` — первая независимая часть Release Core TESSERA. Инструмент **только читает** существующий Git-репозиторий и выдаёт структурированный JSON без записи файлов, коммитов, тегов или сетевых запросов. Не зависит от Codex, Harness, Claude, Hermes и других агентов.

## Что действительно проверяется

- Корневой каталог Git-репозитория и фактический полный SHA целевого коммита.
- Значение `VERSION` **в целевом коммите**, а не в текущей рабочей копии (это позволяет проверять старые релизы).
- Существование Git-тега версии с возможным пространством имён.
- Тип тега: требуется настоящий аннотированный объект `tag`, а не легковесный указатель.
- Непустая аннотация и соответствие целевого SHA конкретному коммиту.
- Дополнительно сообщается, чиста ли текущая рабочая копия; этот факт сам по себе не доказывает готовность релиза.

## Команда

Из корня TESSERA:

```bash
python core/release_inspect.py --repo <project-root> --version 0.1.0
python core/release_inspect.py --repo <project-root> --version 0.1.0 --commit <full-commit-sha>
python core/release_inspect.py --repo <project-root> --version 0.1.0 --prefix microversion-release/
```

`--commit` принимает только полный SHA; без него проверяется HEAD. Поля результата включают `inspection_status`, `release_readiness`, `expected_commit_sha`, `version_in_commit`, `tag_annotated`, `tag_target_commit_sha` и `problems`.

Код 0 означает `inspection_status=PASS`, код 1 — `BLOCKED` или недоступный Git. **PASS здесь означает только согласованность версии и Git-тега.** Поле `release_readiness` намеренно всегда `NOT_VERIFIED`, пока не добавлена независимая проверка сборки и тестов.

## Отрицательные случаи

- `RELEASE_NOT_TAGGED` — тег отсутствует.
- `TAG_NOT_ANNOTATED` / `TAG_ANNOTATION_MISSING` — легковесный тег или пустая аннотация.
- `TAG_WRONG_COMMIT` — тег указывает на другой коммит.
- `VERSION_MISSING_IN_COMMIT` / `VERSION_MISMATCH` — нет или не совпадает записанный номер версии.
- `TAG_TARGET_NOT_COMMIT` — тег невозможно сопоставить с коммитом.

## Следующая часть Release Core — T09.02

Отдельный [Release Preflight](RELEASE_PREFLIGHT.md) проверяет версию, записи CHANGELOG и доверенный план обязательных сборок/тестов. Режим `--plan` ничего не исполняет; режим `--execute` запускает объявленные команды только после явного разрешения. Это **другой компонент**: данный инспектор тегов остаётся полностью read-only. Даже успешный preflight не означает, что тег создан или приложение опубликовано.

## Проверка удалённого тега

Отдельная стадия [T09.03](RELEASE_REPORT.md) проверяет наличие **того же объекта аннотированного тега** на доверенном удалённом Git и формирует отчёт по наблюдаемым фактам. Локальный инспектор T09.01 не обращается в сеть и не меняется по назначению.

## Чего инструмент пока не делает

- Не выполняет build/test, не читает доказательства их успеха.
- Не анализирует CHANGELOG целевого приложения, подписанные релизы и пакетные манифесты.
- Не отправляет теги на remote, не проверяет опубликованные теги или GitHub Release.
- Не формирует окончательное решение RELEASED и не сериализует конкурентные релизы.
- Предполагает файл `VERSION` в целевом проекте; другие системы хранения версий будут подключаться отдельно.

Это **T09 PARTIAL**, а не готовая система релизов. Будущая логика preflight, build, tag, remote и report будет развиваться на основе независимых проверок, а не сообщений модели.

## Тестирование

```bash
python -m unittest discover -s tests -v
```

Тесты используют временные Git-репозитории и не изменяют другие проекты.

## T12.03.11 — локальная инспекция фиксированных объектов (кандидат)

Общий read-only Git helper для inspect/preflight/report отвергает наследуемый контекст Git, передаёт только явный список переменных без identity/signing/auth, использует --no-replace-objects, --no-optional-locks, отключает fsmonitor, запрещает интерактивный prompt и запрашивает отказ lazy fetch. 30 секунд на вызов, закрытый stdin, фиксированные коды ошибок без сырого stderr. Доверенные Git/PATH, конфигурация и файловая система остаются предпосылками; это не жёсткая квота памяти, не сетевой sandbox, не доказательство отсутствия всех побочных эффектов. Проверка тега читает фиксированный SHA, требует прямой commit и имя тега внутри объекта, сверяет ref повторно; для текущего HEAD повторно сверяет commit, исторический режим требует точного commit SHA, не SHA tag object. JSON schema v1 сохранена. Восемь новых регрессий; реальный CI необходим. Не защищает от ABA/TOCTOU после проверки, remote subprocess и команды пользовательского preflight имеют отдельные контракты. T15 открыт.

## T12.03.12 — удалённая инспекция (кандидат)

Только настроенный remote с одним effective fetch URL; абсолютный локальный путь/file, HTTPS и SSH, без HTTP/git/ext, пароля или HTTPS userinfo. GIT_ALLOW_PROTOCOL допускает file:https:ssh, фиксированный upload-pack, отказ HTTP redirects, закрытый stdin и минимальное окружение; SSH_AUTH_SOCK разрешён для явно запрошенного remote. Доверенные Git config, credential helpers, SSH config, HOME/PATH и сервер остаются предпосылками. Нет сетевого sandbox или гарантии остановки descendants; повторная проверка не устраняет ABA/TOCTOU. После запроса сверяются локальное доказательство и URL; объединённый отчёт сверяет commit и SHA объекта. GitHub publication использует тот же URL-контракт. Десять регрессий; CI обязателен. Реальный HTTPS/SSH с аутентификацией NOT_VERIFIED.

## TD17 — явная диагностика наследуемого контекста (кандидат)

Инспектор и локальный теггер отвергают также осиротевшие индексированные переменные GIT_CONFIG_KEY_*/GIT_CONFIG_VALUE_*, даже если GIT_CONFIG_COUNT отсутствует. Диагностика `release_tag.py context` не запускает Git, не меняет окружение, сообщает только известные имена (не значения) и заменяет произвольный суффикс фиксированным GIT_CONFIG_INDEXED_OTHER. Код 1 означает блокирующий контекст; код 0 означает лишь отсутствие известных блокирующих имён в момент наблюдения. Это не разрешение снять ограничения хоста, не проверка доверия и не готовность релиза. Реальный запуск в Codex и безопасный контракт адаптера остаются открытыми (#81).
