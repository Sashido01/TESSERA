# T12.02.02.02 — проверка текстового снимка Gitleaks

[**Русский — оригинал**](GITLEAKS_REVIEW.md) | [English — перевод](GITLEAKS_REVIEW.en.md)

Используется официальный [Gitleaks v8.30.1](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1), MIT. Linux amd64 архив закреплён SHA-256 из metadata официального GitHub Release. Из архива извлекается только исполняемый файл. Не используются GitHub Action Gitleaks, платные услуги, AI API, Tier 2/3 или автоматические установщики NVIDIA.

## Область и защита

- Снимок всех отслеживаемых Git файлов рабочего дерева (в CI — checkout). Каждый непустой UTF-8 файл подаётся отдельно через stdin; пустые учитываются отдельно. Symlink, недопустимые пути, бинарные/не-UTF-8 файлы и превышение лимитов блокируют проверку. Git-история, неотслеживаемые файлы, бинарные и вложенные архивы не проверяются.
- [Upstream issue #2316](https://github.com/gitleaks/gitleaks/issues/2316) сообщает о пропуске текстовых файлов с архивоподобными именами. stdin не передаёт имя файла; проверяется точное число прочитанных байтов каждого файла. Правила, зависящие от имени файла, требуют отдельного исследования; используется встроенная конфигурация и её content allowlists.
- Отдельный временный каталог без конфигурации репозитория и наследуемых ключей; --ignore-gitleaks-allow, --redact=100, отдельный exit code 10 для находок. Не применяются пользовательские baseline, исключения или подавления.
- JSON и stderr захватываются в память, не печатаются и не публикуются как артефакты. Проверяются версия, коды завершения, объём прочитанных данных, отсутствие частичного сканирования, валидность JSON, редактирование поля Secret, неизменность снимка, положительный и отрицательный синтетические сценарии. В итоговом отчёте только агрегаты по кодам правил и группам tests/other.
- Синтетический маркер не является настоящим ключом, формируется только в памяти. Проверяется обнаружение даже с gitleaks:allow и отсутствие маркера в захваченном выводе. Это не доказательство обнаружения всех секретов или защиты произвольных полей отчёта; изоляция окружения не является сетевым sandbox.
- Находки advisory до ручного анализа; сбой выполнения или неполное покрытие блокируют CI. NO_FINDINGS относится только к указанной области и встроенным правилам.

## Запуск и приёмка

`python tools/check_gitleaks_review.py --repo . --cli <путь-к-gitleaks>`

GITLEAKS_REVIEW_EXECUTION_PASS означает подтверждение выполнения контракта, не отсутствие утечек. T12.02.02.02 — COMPLETE в заявленных границах текстового снимка, достижимых UTF-8 blob и пяти правил по пути. Полный NVIDIA Tier 1 и T12 остаются PARTIAL.

## Достижимая Git-история (0.0.30)

Вторая независимая проверка, `python tools/check_gitleaks_history.py --repo . --cli <путь-к-gitleaks>`, инвентаризует объекты, достижимые из локальных refs и HEAD, без подмены Git-объектов; запрещает shallow, проверяет размеры уникальных blob и UTF-8, затем сканирует каждый непустой blob через stdin в ограниченном пуле процессов. Сверяется инвентарь до и после, число байтов и обнаружение синтетического маркера, удалённого в следующем коммите. Бинарные и неподдерживаемые кодировки блокируют проверку; отчёты только агрегированные. Проверяется содержимое, а не правила по именам, не полученные с remote refs, сообщения коммитов, недостижимые объекты или содержимое архивов. [CI 45368434188](https://github.com/Sashido01/TESSERA/actions/runs/45368434188) PASS: 437+19 тестов; 585/585 уникальных UTF-8 blob, 5431003 байта, находок нет, удалённый синтетический маркер PASS, 128,81 с. Находки advisory, ошибки выполнения блокируют CI.

## Правила, зависящие от пути

В upstream v8.30.1 пять правил с явным условием пути: PHP/Freemius, Terraform, Kubernetes YAML, NuGet config, имена PKCS#12. Отдельная проверка перечисляет подходящие пути текущего дерева и уникальные пары (правило, blob) из всех достижимых деревьев коммитов. Каждый кандидат сканируется под каноническим именем, сохраняющим условие правила; проверяется точное байтовое покрытие, используется только целевое правило и синтетическое обнаружение каждого из пяти правил. Это обход ошибки архивоподобных имён, но не полное воспроизведение всех allowlist по путям. Исходные имена и сырые находки не выводятся. Недостижимые объекты и не полученные remote refs не проверяются. [CI 45369335974](https://github.com/Sashido01/TESSERA/actions/runs/45369335974) PASS: 443+19 тестов; 598 уникальных UTF-8 blob, 5639755 байт, 0 находок; пять синтетических правил PASS; 4 текущих YAML-файла, 28 исторических пар правило/blob из 37 коммитов, 0 находок. T12.02.02.02 COMPLETE в заявленных границах.

## T12.03.10 — единый контракт запуска (кандидат)

[CVE-2026-124039](https://github.com/CVEProject/cvelistV5/blob/main/cves/2026/124xxx/CVE-2026-124039.json), опубликована 06.11.2026: Gitleaks до 8.30.1 включительно создаёт файл отчёта с недостаточно строгими правами. В закреплённом [cmd/root.go](https://github.com/gitleaks/gitleaks/blob/83d9cd684c87d95d656c1458ef04895a7f1cbd8e/cmd/root.go#L470) путь '-' использует stdout вместо os.Create. Ранее все три обёртки уже использовали stdout и redact=100. Теперь единая функция фиксирует эти параметры, явную глубину архивов 0 (прежнее upstream default), исключает произвольные параметры отчёта. Два теста контракта и два теста изменения/добавления файла. При живых контрольных сканированиях проверяются имена верхнего уровня временного каталога до и после; при каждом скане по пути — единственный исходный файл и неизменность байтов. Синтетический маркер stdout/stderr по-прежнему проверяется. Это ограниченная проверка побочных эффектов, не мониторинг системных вызовов, не гарантия отсутствия внешних/временных записей и не sandbox. Лимит вывода проверяется после захвата, не является жёстким лимитом памяти. Archives Identify вызывается до проверки глубины: отключение обхода архивов не доказывает недостижимость всех зависимостей. STATIC_MITIGATION_PRESENT; реальная приёмка обязательна. Официальный стабильный Gitleaks остаётся 8.30.1; master 5f6ec56cfa6f8c67648d863582c7ae2f206d5c1c обновил часть зависимостей, но сохраняет Go 1.24.11, x/crypto 0.35.0, x/sys 0.30.0 и os.Create для файлов отчёта. Не заменять stable неподтверждённой сборкой.
