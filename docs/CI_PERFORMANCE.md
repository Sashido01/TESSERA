## Первый кандидат T19.02

Перенос пары host/Docker Gitleaks history в независимую job history_checks. Остальные прежние проверки остаются в catalog_checks. Обе запускаются на том же GitHub SHA с полной историей, без persist credentials, с прежними pinned Actions и обязательным Docker preflight. Образ и бинарник закреплены прежними хешами. Не использовать кеши отчётов и не исключать blobs. Host/container сравнивают один снимок достижимых локальных refs внутри history job; неполученные remote refs не покрыты. Дублируется только минимальная подготовка, не сам аудит.

Обязательный check сохраняет имя validate: всегда запускается и требует result=success от обеих jobs. Отказ, отмена и пропуск обязательной группы не удовлетворяют gate. tag_microversion сохраняет needs: validate. Проверки существующего workflow и закреплённых Actions актуализированы, добавлены регрессионные сценарии. Результат CI нового кандидата пока NOT_VERIFIED. Не назначать корневую микроверсию до интеграционного слота.

Baseline main 45568501762: 943 с; история 488 с. PR 45569400436: 700 с; история 345 с. Идеальный расчёт без дополнительных расходов — max(488,455)=488 с и max(345,355)=355 с; не прогноз фактической скорости. Два runner могут ждать очередь, подготовка и рост каталога влияют на время. Приёмка: сравнить реальные p50/p95 и очередь/runner-minutes по сопоставимым запускам, подтвердить обязательность обеих групп и тег. Если нет выигрыша — измерить причину, не усложнять систему ради количества jobs.

Локальный контроль Bash (25.11.2026): все 16 сочетаний success/failure/cancelled/skipped — PASS, только success/success принят; отсутствие каждой из двух переменных отвергнуто (2/2). Это проверка логики команды, не доказательство планирования GitHub. В CI добавлен повторяемый контроль и проверка named jobs в Release Core.

## T19.03 — второй кандидат параллелизма

Из main v0.0.69 (CI 45584865396): 625 с до validate, catalog 621 с, history 401 с. Четыре самостоятельных шага Gitleaks source/path заняли 111+66+25+25=227 с; интегрированный NVIDIA Tier 1 (129 с) остаётся в catalog. Перенос только четырёх шагов в source_secret_checks, сохраняя host/container пары в одной job, точный SHA, полный checkout, pinned Gitleaks и Docker preflight; каталог сохраняет Gitleaks для интегрированного Tier 1 и проверки Go. История и tag job побайтово не меняются. Итоговый validate требует успеха трёх групп. В тестах предусмотрены 64 комбинации статусов (4³) и три отсутствующих переменных, контроль обязательного source scope, трёх групп в независимом отчёте. Старые две группы сохраняют совместимость отчётов; наличие source job требует обе исходные группы. Без проверки исторической конфигурации отсутствие целой новой группы в подложных данных API этим отчётом не обнаруживается; реальный gate обязателен. Теоретический максимум без накладных расходов: max(621−227,401,227)=401 с, не прогноз. Третий runner увеличивает расходы и может ждать очередь; принять только после реального CI и измерения. NOT_VERIFIED, версия ещё не назначена.
