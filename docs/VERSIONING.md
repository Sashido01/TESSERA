# Политика версий TESSERA и навыков

## Два уровня истории

У каталога TESSERA есть собственная версия. У каждого навыка — независимая версия. Не подменяйте ими версии приложений, которые используют навыки.

Начальное состояние нового проекта: `0.0.0`. Для навыков с независимыми тегами используйте пространство имён, например `microversion-release/v0.1.0`. Для общего каталога можно использовать `v0.1.0`, если не существует конфликта.

## Рабочие микроверсии

- Самостоятельное проверенное изменение: увеличение PATCH на 1.
- После `.99` при незавершённой задаче разрешены `.100`, `.101` и далее, без искусственного ограничения на 99.
- Нельзя придумывать изменения ради увеличения номера, а оформление текущей версии не порождает бесконечных новых версий.
- На новых проектах плановый рубеж: `0.0.99 → 0.1.0`, `0.1.99 → 0.2.0`, `0.99.99 → 1.0.0`.
- Если задача продолжилась до `0.0.107`, после её завершения и необходимых проверок возможен переход `0.0.107 → 0.1.0`; пропущенные цифры не требуется заполнять.
- Проверки и сборки обязательны в той мере, в какой они установлены для проекта. Не объявляйте релиз готовым, если обязательные проверки не прошли.

## Человекочитаемые сообщения

Название коммита объясняет *что изменилось*, а не факт запуска инструмента. Пример: «Добавлена проверка корректности навыка перед публикацией». Тег — машинное имя, его аннотация — понятное описание. Release Notes указывают проверенные факты и ограничения.

## Ограничение

Эта политика — особый выпускной процесс TESSERA, а не утверждение о стандартной практике SemVer: внешние пакеты и API могут требовать иной схемы. Не изменяйте задним числом историю существующих проектов и опубликованные теги.
