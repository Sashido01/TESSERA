# Политика версий TESSERA и навыков

[**Русский — оригинал**](VERSIONING.md) | [English — перевод](VERSIONING.en.md)

## Два уровня истории

У каталога TESSERA есть собственная версия. У каждого навыка — независимая версия. Не подменяйте ими версии приложений, которые используют навыки.

Начальное состояние нового проекта: `0.0.0`. Для навыков с независимыми тегами используйте пространство имён, например `microversion-release/v0.1.0`. Для общего каталога можно использовать `v0.1.0`, если не существует конфликта.

## Применение непосредственно к TESSERA

**TESSERA подчиняется этим правилам в полном объёме.** Речь идёт о версии корневого каталога, отдельно от самостоятельных версий вложенных навыков. Историческая начальная версия — `0.0.0`; ранее опубликованная история без обязательного `VERSION` остаётся без изменений. Новая схема начинает действовать с `0.0.1`.

- Единственный машинно-читаемый номер версии каталога находится в корневом файле [`VERSION`](../VERSION).
- Каждое самостоятельное проверенное изменение репозитория — один коммит с новой микроверсией и записями в `CHANGELOG.md` и `CHANGELOG.en.md`.
- CI проверяет строгий переход относительно родительского коммита: обычный PATCH+1 либо релизный переход к следующему `.0` только после PATCH≥99. Первая миграционная запись должна иметь номер `0.0.1`.
- Коммит называется по-русски, содержательно и без шаблонных `bump` / `chore`. После успешной проверки коммита `main` GitHub Actions создаёт **аннотированный** тег `vX.Y.Z` с русским названием; повторная публикация и изменение существующего тега запрещены.
- Для самого TESSERA выпуск `.0` — выпуск каталога и документов/скриптов; отдельный бинарный дистрибутив не обязателен. Релиз допустим только после тестов и проверки полноты документации; GitHub Release создаётся отдельно после подтверждения готовности.
- Новый коммит, меняющий только служебные метаданные текущей версии, не должен порождать дополнительную бессмысленную микроверсию. Проверки и подготовка версии входят в одну операцию.

## Обязательный тег каждого релиза

**Каждый релиз TESSERA и каждого навыка требует аннотированного Git-тега**, который указывает на релизный коммит. Имя каталога: `vMAJOR.MINOR.PATCH`; независимого навыка: `<skill>/vMAJOR.MINOR.PATCH`. При выпуске `0.1.0`, `0.2.0`, `1.0.0` и аналогичных `.0` отсутствие такого тега означает `BLOCKED / RELEASE_NOT_TAGGED`, даже если документация или сборка готовы. Тег должен содержать конкретное русское описание. Не создавайте легковесные теги, не меняйте существующие и не называйте локальную фиксацию публикацией на GitHub.

Для проектов, использующих навык, предусмотрена проверка `scripts/release_tag.py verify`; CI и Git Hooks могут обеспечивать независимую обязательность. Локальная проверка тега не доказывает, что все целевые платформы поддерживают автоматическую активацию навыка.

## Рабочие микроверсии

- Самостоятельное проверенное изменение: увеличение PATCH на 1.
- После `.99` при незавершённой задаче разрешены `.100`, `.101` и далее, без искусственного ограничения на 99.
- Нельзя придумывать изменения ради увеличения номера, а оформление текущей версии не порождает бесконечных новых версий.
- На новых проектах плановый рубеж: `0.0.99 → 0.1.0`, `0.1.99 → 0.2.0`, `0.99.99 → 1.0.0`.
- Если задача продолжилась до `0.0.107`, после её завершения и необходимых проверок возможен переход `0.0.107 → 0.1.0`; пропущенные цифры не требуется заполнять.
- Проверки и сборки обязательны в той мере, в какой они установлены для проекта. Не объявляйте релиз готовым, если обязательные проверки не прошли.

## Человекочитаемые сообщения

Название коммита объясняет *что изменилось*, а не факт запуска инструмента. Пример: «Добавлена проверка корректности навыка перед публикацией». Тег — машинное имя, его аннотация — понятное описание. Release Notes указывают проверенные факты и ограничения.

## Ограничение

Эта политика — особый выпускной процесс TESSERA, а не утверждение о стандартной практике SemVer: внешние пакеты и API могут требовать иной схемы. Не изменяйте задним числом историю существующих проектов и опубликованные теги.
