# T10.01 — установка навыков официальным GitHub CLI в изоляции

[**Русский — оригинал**](GH_SKILL_INSTALL.md) | [English — перевод](GH_SKILL_INSTALL.en.md)

## Область проверки

В T10 выбран официальный [`gh skill install`](https://cli.github.com/manual/gh_skill_install) вместо стороннего менеджера. Команда находится в preview: флаги и механика могут изменяться.

T10.01 проверяет **локальный режим** `gh skill install <source> microversion-release --from-local --dir <destination>`, обнаружение результата с `gh skill list --dir`, сохранность исходных файлов и запрет опасного повторного размещения. Никакая настоящая пользовательская папка, профиль агента или GitHub Release при тестах не изменяются.

Удалённая установка **по тегу или SHA** из `Sashido01/TESSERA` проверяется отдельным сценарием T10.02 ниже. Наличие установленного файла не доказывает загрузку навыка в работающем Codex, Harness, Claude Code или Hermes: это T03/T05.

## Известная опасность официального CLI

Исходники **официального GitHub CLI `v2.105.0`** (исходная ревизия `e1219499a578b69e3437adaa31cd60614e23c802`) показывают два ограничения:

1. `--from-local` и `--pin` **взаимоисключающие** параметры. При локальной установке нельзя заявлять, что навык закреплён по Git-тегу или commit SHA.
2. В локальном методе `InstallLocal` файлы копируются через `os.WriteFile` с сохранением относительной структуры, но **без проверки, что одноимённый каталог и файлы уже существуют**. Поэтому непосредственное повторное выполнение `gh skill install --from-local --dir ...` может перезаписать файлы пользователя даже без `--force`. Это предмет отдельной негативной проверки и причина не устанавливать CLI напрямую в существующий профиль.

Официальный `gh skill install` **не предлагает `--dry-run`**. Не путайте его с `gh skill publish --dry-run` (валидатор формата) или `gh skill update --dry-run` (проверка обновлений).

## Безопасная приёмка в CI

- Используется **тот же** GitHub CLI `2.105.0`, что для T11.02: официальный Linux AMD64 архив с SHA-256 `79e7ab5db738c48777b696e374f8b428f0647debfb424f44d2f426370407fe2f`. CI сверяет архив **до** распаковки и исполнения.
- Скрипт `tools/check_official_local_install.py` копирует только проверенные файлы `skills/` во временную папку и проверяет отпечаток содержимого SHA-256 до и после.
- Запуск `gh skill install` производится **только** во временную ранее пустую директорию с отдельным HOME/GH_CONFIG_DIR, без наследованных GitHub токенов, Git remote и пользовательского Git-конфига.
- Проверяются наличие `microversion-release/SKILL.md`, сохранность Markdown тела, точность `references/INTEGRATION.md` и инъекция источника в метаданные установленного навыка.
- `gh skill list --dir` должен реально обнаружить установленный навык.
- Факт конфликта `--from-local --pin` проверяется только на дополнительной пустой папке: результат обязан быть отказом, не установкой.
- Встроенная функция `safe_destination` **отказывает до запуска CLI**, когда целевой каталог существует, даже если это каталог пользователя с изменёнными файлами. Никакой разрушительный повторный вызов CLI в реальной пользовательской папке не производится.

## Ручные действия

В существующих проектах до проверки полного T10 использовать [встроенный офлайн-установщик](../skills/microversion-release/references/INTEGRATION.md): по умолчанию он показывает DRY-RUN, а с `--apply` явно копирует **только если целевого каталога нет**.

Официальный CLI при локальном использовании допустим **только в собственном новом пустом целевом каталоге**, после изучения исходного навыка. Для установки из GitHub в будущем:

~~~text
gh skill install Sashido01/TESSERA microversion-release --pin vX.Y.Z --dir <new-empty-skills-dir>
~~~

Использовать полный ref `refs/tags/vX.Y.Z` вместо короткого имени во избежание неоднозначности. `--pin` относится к **GitHub-режиму**, а не к `--from-local`. При непонятном состоянии существующей установки не применять `--force`.

## T10.02 — удалённая установка с закреплением

Официальный `gh 2.105.0` разрешает короткое имя сначала как ветку, затем как тег, затем как commit SHA. Поэтому фиксированная проверка TESSERA использует **полный** `refs/tags/v0.0.22` и отдельно commit `34923e27e669da0092440a0bbfb00b2dfdd98a37`. Независимый ожидаемый tag object: `b9967ac3aa1abac7fdb8e7abceb8c6a3f79da66c`. Источник: [resolveExplicitRef / resolveTagRef в официальном CLI v2.105.0](https://github.com/cli/cli/blob/v2.105.0/internal/skills/discovery/discovery.go).

`tools/check_official_remote_install.py` проверяет оба pin через **действительный** официальный CLI. Два отдельных новых временных каталога; отдельные HOME и GH_CONFIG_DIR; только read-only короткоживущий токен CI (`github.token`, без PAT и токена пользователя). Git-проверка не получает этот токен. Точный набор файлов и байты берутся из независимо проверенного Git tree аннотированного тега; для SKILL.md сравниваются Markdown-тело и метаданные github-repo, github-path, github-ref, github-pinned, github-tree-sha. Полная семантическая эквивалентность YAML frontmatter не заявляется. `gh skill list --dir --json` подтверждает pin, источник и версию. `gh skill update --dry-run` должен пропустить оба pinned навыка без изменений; повторная установка в одноразовый каталог без --force обязана быть отклонена без изменения файлов. Скрипт не запускает содержимое навыка.

**Результат реальной приёмки T10.02 (24.11.2026): COMPLETE.** [GitHub Actions 45351217500](https://github.com/Sashido01/TESSERA/actions/runs/45351217500) SUCCESS, официальный gh 2.105.0 сообщил `GH_SKILL_REMOTE_PIN_PASS`: tag_install, sha_install, pinned_update_dry_run, duplicate_install_refusal — PASS. Ожидаемое Git tree навыка `4ed1f6095092b51cfd80d12f68865eecc6f86398` совпало с метаданными обеих установок; состав и байты вспомогательных файлов, Markdown-тело SKILL.md и pin проверены. 362 теста каталога и 19 тестов навыка PASS. Это проверка установки с CI token в Linux, не активация в агенте.

Критерий: реальный CI со строкой `GH_SKILL_REMOTE_PIN_PASS`; mock-тесты не доказывают удалённую установку. На этапе T10.02 не проверены применённое обновление с --unpin, несколько навыков с конфликтующими именами/независимыми тегами, активация в клиентах, неавторизованное API. Не обещать автоматическое обновление до последнего Git-тега: по исходникам CLI без явного ref сначала выбирает последний GitHub Release, при его отсутствии — default branch. Не использовать --force в существующем профиле.

Пример безопасной отдельной установки после PASS CI (новая пустая папка; предварительно изучить навык):

~~~text
gh skill install Sashido01/TESSERA microversion-release --pin refs/tags/v0.0.22 --dir <new-empty-skills-dir>
~~~

## T10.03.01 — фактическое обновление и контролируемый re-pin

Исследован исходный код [официального gh 2.105.0, update.go](https://github.com/cli/cli/blob/v2.105.0/pkg/cmd/skills/update/update.go). `--unpin` снимает закрепление для поиска обновления, но не выбирает новый конкретный тег. CLI разрешает последний GitHub Release, при отсутствии релиза — default branch. При успешном обновлении он заменяет содержимое каталога; пользовательские правки и дополнительные файлы могут исчезнуть. В исходниках rollback вызывает операции с игнорированием некоторых ошибок восстановления. Это не гарантия восстановления при любых сбоях.

`tools/check_official_skill_update.py` использует только одноразовое окружение CI, read-only токен, фиксированные аннотированные теги v0.0.5 и v0.0.23 с разными Git tree. Для нативного обновления ожидаемые файлы берутся из точного SHA удалённой main, проверенного до/после операции. Сценарий проверяет реальное `update --unpin --dry-run`, затем `--unpin --all` исключительно над синтетическими локальными правками; отсутствие этих правок после обновления считается подтверждением риска, а не достоинством. Проверяется действительный новый Git tree, отсутствие pin и точный состав файлов.

Безопасный сценарий для точного re-pin не использует `--force` и не обновляет рабочий каталог напрямую: независимо устанавливает старую и новую версии, сверяет все записи (включая скрытые и дополнительные, режим, размеры, SHA-256), блокирует локальные изменения и подмену staging, перемещает старую копию в backup и новую в целевой каталог на одном томе. Проверяются инъекция отказа после перемещения старой копии, восстановление исходных байтов и явный откат после успеха с сохранением новой копии. Ссылки, hardlinks, вложенные/совпадающие пути и существующий backup запрещены. При ошибке отката helper не удаляет резервную копию; весь CI-тест использует удаляемые временные данные.

Это **испытательный стенд, не готовый инструмент обновления реального профиля**. Требуется эксклюзивное владение каталогом; устойчивость к аварийному завершению процесса, concurrent writers, подмене родительских путей, Windows и активным клиентам не доказана. Нельзя автоматически сливать пользовательские изменения или применять к существующим установкам. T10.03.02 отдельно исследует несколько навыков, коллизии и отдельные теги без публикации фиктивных навыков в TESSERA. Реальная приёмка T10.03.01 — по `GH_SKILL_UPDATE_PASS` в CI.
