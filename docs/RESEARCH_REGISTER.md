## Repository Workflow
- GitHub Flow + короткие ветки и trunk-based integration; stacked PR только для реальной зависимости, постоянная develop не нужна. Монорепозиторий с независимыми версиями. Worktrees разделяют файлы, но не все refs и ресурсы: [Git worktree](https://git-scm.com/docs/git-worktree).
- Нативные [Issue dependencies](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-issue-dependencies), [merge queue](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue?apiVersion=2022-11-28) (для организаций), [required checks](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks?apiVersion=2022-11-28), [gh pr merge](https://cli.github.com/manual/gh_pr_merge), [concurrency](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency), [dependency caching](https://docs.github.com/en/actions/concepts/workflows-and-actions/dependency-caching), [reusable workflows](https://docs.github.com/en/actions/concepts/workflows-and-actions/reusing-workflow-configurations). Новые возможности queue, parallel steps, lockfiles Actions и event listening исследовать на текущем аккаунте, не считать доступность доказанной.
- Аналоги: [Superpowers](https://github.com/obra/superpowers) — worktree, TDD, разделение задач; [Spec Kit](https://github.com/github/spec-kit) — спецификации и зависимости; [Beads](https://github.com/gastownhall/beads) — ready work; [Worktrunk](https://github.com/max-sixty/worktrunk) — worktrees; Git Workflow Skill, Agent Collab, Task Orchestrator, Vibe Kanban — кандидаты. Не требовать установки.
- [Changesets](https://github.com/changesets/changesets) и [Release Please](https://github.com/googleapis/release-please) — отделение намерения от выпуска; [Nx affected](https://nx.dev/docs/features/ci-features/affected) — анализ области влияния. TESSERA сохраняет собственную микроверсионность и минимальные средства.
- [Effective Strategies for Asynchronous Software Engineering Agents / CAID](https://arxiv.org/abs/2603.21489), [AsynCodeBench](https://arxiv.org/abs/2609.32662), [ParallACT](https://arxiv.org/abs/2611.00314): разделение областей, зависимости, координация и семантические конфликты. NP-Bench — кандидат на повторную проверку источника. Не переносить показатели научных экспериментов на TESSERA без benchmark.
- Локальные Git-пробы (25.11.2026, 5/5 по предыдущему выполнению): ранний общий VERSION конфликтует; позднее назначение и последовательные squash/tag работают; текстово чистый merge может сломать поведение; worktrees разделяют файлы, но теги общие; atomic push конфликтующих тегов в bare remote отклоняет весь набор. Реальный GitHub atomic push/Rulesets не проверен.

## Project Audit
- Аналоги project-audit-skill, Codebase Audit, Repo Audit, All Audits, OpenAudit: методология, инвентаризация, независимый challenge, модульность и отчёт. Нет обязательного копирования сторонних навыков.

Динамические проверки и защита от indirect prompt injection. Инструмент не равен доказанной применимости CVE.
- [RIG](https://arxiv.org/abs/2601.10112), [How Should Agents See Code?](https://arxiv.org/abs/2611.07286), [Agent Retrieval Bench](https://arxiv.org/abs/2607.24882): карта компонентов и тестов, разные представления кода, адаптивный поиск контекста и отсутствие подходящего контекста. RepoReason/RepoProbe, TraceLLM/TraceDev, Graph2Env — дальнейшая проверка методик. Семь логических графов: структура, семантика, зависимости, требования, проверки, история, доказательства; без обязательной графовой БД.
- [VerifierBench](https://arxiv.org/abs/2610.28679), SWE-ABS, CR-Bench-v2, ReviewBench: качество проверяющих, negative controls, отдельные precision/recall и проверка новых замечаний. Property/metamorphic/differential/fault injection/fuzz/mutation/contract/model checking/symbolic execution/slicing — опциональные профили, Hypothesis, fast-check, cargo-fuzz, Schemathesis, Pact, Z3, TLA+/TLC.
- Looping Is Not Reliability, Graph2Env, SpecBench: привязка результата к снимку, окружению, конфигурации, выявление слабостей процесса. DELTA только при достаточной карте зависимостей; SHA одного коммита недостаточно для грязного дерева. Исторический CI не подтверждает новый снимок.
- [SkillsBench](https://www.skillsbench.ai/) — сравнение с навыком/без навыка; NVIDIA Tier 1 static-only; Runtime Skill Audit и MalSkillBench — направления изучения фактических действий. Реальные поведенческие evals обязательны, без Tier 2/3 и обязательных платных API. Метрики: recall, precision, ложные COMPLETE, evidence accuracy, coverage, stale evidence, source integrity, resume, токены и время. Не сводить всё к одному баллу.

## Исследования 26.11.2026 — TD17/T13, TD04, Project Audit, Repository Workflow

- **TD17:** [исходник Codex Windows sandbox](https://github.com/openai/codex/blob/main/codex-rs/windows-sandbox-rs/src/sandbox_utils.rs) внедряет safe.directory через GIT_CONFIG_COUNT/KEY/VALUE. [Upstream issue #63115](https://github.com/openai/codex/issues/63115) описывает 10 пар config в Windows Desktop и пропавшие пустые значения. Это пользовательский отчёт, не доказательство причины конкретного профиля TESSERA. Не удалять переменные автоматически, не принимать произвольные config overrides; сначала диагностировать имена, затем изучить нативный безопасный интерфейс хоста. Ключи/значения и состояние безопасности не публиковать. Реальная приёмка открыта.
- **T13:** [Codex hooks](https://learn.chatgpt.com/docs/hooks) и экспериментальный [dsh-hooks-codex](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/experimental/hooks-codex/README.md) дают возможность исследовать один переносимый протокол Stop/PreToolUse/PostToolUse; не считать экспериментальную совместимость эквивалентной блокировке релиза. Проверять разрешения, ошибки, повторный вызов и отсутствие хука; независимый Git/CI gate обязателен. Не включать плагины автоматически.
- **TD04:** [git cat-file --batch](https://git-scm.com/docs/git-cat-file) уменьшает число процессов чтения. Одноразовый Linux fixture, Git 2.47.3, 256 уникальных blob, 74050 байт, три повтора: медиана отдельных cat-file 0.50815 с, batch 0.01379 с (~36.8x только чтение). Проверены точные байты, порядок, тип, длина и SHA-1 256/256. Это прототип без Gitleaks, не CI benchmark. Следующий кандидат: ограниченные chunks, проверка framing/OID/размера/EOF и дедлайна; обязательная повторная инвентаризация и host/container parity. [GitHub cache security](https://docs.github.com/en/actions/concepts/workflows-and-actions/dependency-caching): cache недоверен, не переносить PASS из PR; не кешировать вердикты до проверки trust model.
- **Project Audit:** [SARIF 2.1.0](https://docs.oasis-open.org/sarif/sarif/v2.1.0/sarif-v2.1.0.html) предлагает fingerprints/baselineState. Разделять идентичность находки и свежесть evidence; сопоставление не заменяет перепроверку. DELTA должен инвалидировать изменённые зависимости, конфигурацию, версию анализатора и неполный scope; не объявлять исчезновение находки исправлением без проверки. [Codex Security workflow-routing evals](https://github.com/openai/codex-security/blob/main/evals/workflow-routing/README.md) — пример проверки фактической загрузки навыка в новой сессии; сравнивать со стендом без навыка, фиксировать ложные активации и действия, не только ответ модели.
- **Repository Workflow:** [git worktree](https://git-scm.com/docs/git-worktree) поддерживает machine-readable list --porcelain, lock и prune dry-run. Включить в будущий read-only inventory, не удалять ветку только по ancestry после squash; сравнить принятые blobs/patch, открытые PR и локальное использование. [Git refs API](https://docs.github.com/en/rest/git/refs?apiVersion=2022-11-28) описывает удаление refs; текущий коннектор не предоставляет DELETE, действие владельца после проверки worktrees. Не удалять историю Actions ради счётчика.

Результаты: первичные источники изучены, прототип batch и отдельные проверки диагностики выполнены; новые внешние зависимости, настройки хоста и security gates не изменены. Полный CI и продуктовая приёмка обязательны.

## 26.11.2026 — консервативная инвалидация DELTA и рабочие деревья

- [Bazel Skyframe](https://be.bazel.build/designs/skyframe.html): граф зарегистрированных зависимостей и обратное транзитивное замыкание изменений. Переносим принцип, а не зависимость от Bazel; при неполном графе или изменённом контексте полный повторный аудит. Change pruning пока не применять: результат проверки не доказательство, если изменён неучтённый вход. Кандидат delta_plan.py не исполняет аудит и не переносит PASS; 14/14 изолированных тестов, цепочка 1500 узлов. Реальная приёмка открыта.
- [in-toto validation model](https://github.com/in-toto/attestation/blob/main/docs/validation.md): проверка доверенного подписанта, типа statement/predicate и хеша субъекта — разные стадии. Для уровня V Project Audit это ориентир независимой верификации; не утверждать подлинность только по SHA или имени source.
- [Git worktree](https://git-scm.com/docs/git-worktree): porcelain -z, bare/detached/locked/prunable. Удаление ветки после squash требует проверки уникальных изменений, локальной занятости и статуса PR; prunable не разрешает удаление рабочего дерева. Сначала отдельный read-only parser с NUL-framing, без публикации путей/причин lock; два наблюдения и отказ при неизвестном формате, затем проверка GitHub. Не автоматизировать удаление на этом этапе.

## 26.11.2026 — fail-open у lifecycle hook и внешний контроль

- [Codex Hooks](https://learn.chatgpt.com/docs/hooks): Stop запрашивает продолжение; проектные хуки требуют review/trust, неизвестные и отключённые могут не исполняться. [Harness bridge](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/experimental/hooks-codex/README.md): Stop всегда получает false, continue:false не исполняется, config/exec errors не блокируют весь агент. Одноразовый owner marker ограничивает steering, внешний gate обязателен. Реальный клиент ещё не принят.
- [Codex non-interactive](https://learn.chatgpt.com/docs/non-interactive-mode): process exit и JSON пригодны для внешней проверки, но текст не доказательство. Guarded Run проверяет фактическое состояние Git и тесты отдельно. 26/26 локальных тестов, 16+10; без реального агента.
- [GitHub REST immutable releases](https://docs.github.com/en/rest/repos/repos?apiVersion=2022-11-28): актуальный API 2026-03-10: GET настройки возвращает 200 и enabled:true при включении, PUT включения — 204, 404 не доказывает включение. Подготовить draft, сверить bytes до неизменяемой публикации. [gh release verify](https://cli.github.com/manual/gh_release_verify), [verify-asset](https://cli.github.com/manual/gh_release_verify-asset) независимы от workflow attestation.
