# T11.02 — реальная проверка через gh skill publish --dry-run

[**Русский — оригинал**](GH_SKILL_PUBLISH_DRY_RUN.md) | [English — перевод](GH_SKILL_PUBLISH_DRY_RUN.en.md)

## Проверяемое поведение

Официальная [команда GitHub CLI](https://cli.github.com/manual/gh_skill_publish) `gh skill publish --dry-run` проверяет соответствие Agent Skills и, в отличие от `gh skill publish`, не создаёт GitHub Release. Интерфейс команды находится в preview и может изменяться.

В TESSERA при каждом PR и push в `main` запускается действительный `gh 2.105.0`, а не замена/заглушка, на временном снимке каталога навыков. По итогам требуются два результата: корректный навык принят, навык с несовпадающим именем отвергнут. CI обязан завершиться ошибкой, если попытка запуска не удалась, результат непонятен, CLI изменил файлы или сделал доступным GitHub remote.

## Неподвижный бинарный файл

- Источник: официальный [GitHub CLI 2.105.0](https://github.com/cli/cli/releases/tag/v2.105.0), Linux AMD64 `gh_2.105.0_linux_amd64.tar.gz`.
- SHA-256 архива, сверенный по официальным GitHub Release metadata: `79e7ab5db738c48777b696e374f8b428f0647debfb424f44d2f426370407fe2f`.
- Архив скачивается по HTTPS, его SHA-256 сверяется **до** распаковки и выполнения. Ничего не устанавливается глобально в ОС раннера. Путь бинарного файла передаётся скрипту явно; он также проверяет версию из `gh version`.
- Дополнительный код `tools/run_publish_dry_run.py` использует только стандартную библиотеку Python, Git и временное хранилище.

## Безопасность

`tools/run_publish_dry_run.py` создаёт временный каталог и копирует туда только дерево `skills/`. У снимка нет Git remotes, наследованных GitHub tokens, прав на публикацию и пользовательской Git-конфигурации; для GitHub CLI установлены `GH_PROMPT_DISABLED=1` и отдельный `GH_CONFIG_DIR`. Вызов производится как массив аргументов subprocess (без shell). Установлен timeout.

Для каждого действительного запуска:

1. Проверяются имена и symlink в дереве навыков; вычисляется SHA-256 отпечаток полного дерева.
2. Подготавливается снимок, проверяется его побайтовое совпадение с оригиналом.
3. Официальный `gh skill publish --dry-run` должен завершиться успешно с сообщением о dry-run; отпечаток снимка после команды остаётся неизменным.
4. В **копии** первого SKILL.md имя меняется на несоответствующее каталогу. Команда обязана отклонить результат и не менять повреждённый тестовый файл.
5. Проверяется отсутствие добавленного remote и изменение исходного дерева навыков проекта.

В публичном отчёте фиксируются только статус, версия CLI и коды ограничений. Нет вывода токенов, частных абсолютных путей или сырых сообщений об ошибках стороннего процесса.

## Важная граница доказательств

Режим без remote не выполняет дополнительные серверные проверки тем, настроек безопасности GitHub или опубликованных релизов. Поэтому результат **подтверждает реальную локальную проверку публикационного формата**, но не полностью подтверждает готовность публичной публикации в GitHub и не доказывает работу навыка в агентском клиенте.

Настоящий `gh skill publish`, `--tag` без `--dry-run` или `--fix` не вызываются. Новый GitHub Release не создаётся. Отдельные задачи: T09.10 (подписанный ZIP), T10 (установка через GitHub CLI), T03/T05 (реальные клиенты).

## Приёмка

T11.02 для локального безопасного dry-run = COMPLETE только после успешного GitHub Actions CI с **фактически скачанным, проверенным по хешу и запущенным** `gh`, положительным и отрицательным сценариями. Общий T11 остаётся PARTIAL в части независимого публичного публикационного процесса и совместимости агентских клиентов.
