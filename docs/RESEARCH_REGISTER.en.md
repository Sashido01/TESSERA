## Repository Workflow
- GitHub Flow + short-lived branches and trunk-based integration; stacked PR only for actual dependencies, no permanent develop. Monorepo with independent versions. Worktrees separate files but not all refs/resources: [Git worktree](https://git-scm.com/docs/git-worktree).
- Native [Issue dependencies](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-issue-dependencies), [merge queue](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue?apiVersion=2022-11-28) (organization), [required checks](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks?apiVersion=2022-11-28), [gh pr merge](https://cli.github.com/manual/gh_pr_merge), [concurrency](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency), [dependency caching](https://docs.github.com/en/actions/concepts/workflows-and-actions/dependency-caching), [reusable workflows](https://docs.github.com/en/actions/concepts/workflows-and-actions/reusing-workflow-configurations). Investigate new queue, parallel steps, Actions lockfiles and event listening on actual account; do not assume availability.
- Analogues: [Superpowers](https://github.com/obra/superpowers) — worktree, TDD, task separation; [Spec Kit](https://github.com/github/spec-kit) — specifications and dependencies; [Beads](https://github.com/gastownhall/beads) — ready work; [Worktrunk](https://github.com/max-sixty/worktrunk) — worktrees; Git Workflow Skill, Agent Collab, Task Orchestrator, Vibe Kanban — candidates. No mandatory installation.
- [Changesets](https://github.com/changesets/changesets) and [Release Please](https://github.com/googleapis/release-please) — separate change intent from release; [Nx affected](https://nx.dev/docs/features/ci-features/affected) — impact analysis. Keep TESSERA microversion policy and minimal tools.
- [Effective Strategies for Asynchronous Software Engineering Agents / CAID](https://arxiv.org/abs/2603.21489), [AsynCodeBench](https://arxiv.org/abs/2609.32662), [ParallACT](https://arxiv.org/abs/2611.00314): scopes, dependencies, coordination and semantic conflicts. NP-Bench — source to recheck. Do not transfer experimental figures to TESSERA without benchmarks.
- Local Git probes (25 November 2026, 5/5 in earlier execution): early shared VERSION conflicts; late assignment and serial squash/tag work; textually clean merge can break behavior; worktrees separate files but share tags; atomic push of conflicting tags to a bare remote rejects the entire set. Live GitHub atomic push/Rulesets not verified.

## Project Audit
- Analogues project-audit-skill, Codebase Audit, Repo Audit, All Audits, OpenAudit: method, inventory, independent challenge, modularity and reports. No mandatory copying of third-party skills.
- Inventory/retrieval: scc, ripgrep, Tree-sitter, ast-grep, Repomix, Ctags, SCIP/LSP; architecture: CodeScene/Code Maat, SonarQube, ArchUnit, dependency-cruiser, Import Linter, Madge, Joern, CodeQL; language profiles Ruff/mypy/Pyright, Clippy, ESLint/Biome, Staticcheck, clang-tidy, PMD, Roslyn, ShellCheck. Prefer native tools; others optional.
- Security: Gitleaks, Bandit, Semgrep, Govulncheck, OSV, Syft/Grype, Trivy, OpenSSF Scorecard; ISO/IEC 25010 quality model, NASA bidirectional traceability, NIST SSDF; no certification claim. Dynamic checks and indirect prompt injection protection. Tool output is not proof of CVE applicability.
- [RIG](https://arxiv.org/abs/2601.10112), [How Should Agents See Code?](https://arxiv.org/abs/2611.07286), [Agent Retrieval Bench](https://arxiv.org/abs/2607.24882): component/test maps, varied code views, adaptive context retrieval and no relevant context. RepoReason/RepoProbe, TraceLLM/TraceDev, Graph2Env — further review. Seven logical graphs: structure, semantics, dependencies, requirements, checks, history, evidence; no mandatory graph database.
- [VerifierBench](https://arxiv.org/abs/2610.28679), SWE-ABS, CR-Bench-v2, ReviewBench: verifier quality, negative controls, separate precision/recall, evaluate novel findings. Property/metamorphic/differential/fault injection/fuzz/mutation/contract/model checking/symbolic execution/slicing — optional profiles, Hypothesis, fast-check, cargo-fuzz, Schemathesis, Pact, Z3, TLA+/TLC.
- Looping Is Not Reliability, Graph2Env, SpecBench: bind results to snapshot, environment and configuration; identify workflow weaknesses. DELTA only with sufficient dependency map; one commit SHA is insufficient for a dirty tree. Historical CI does not verify a new snapshot.
- [SkillsBench](https://www.skillsbench.ai/) — compare with/without skill; NVIDIA Tier 1 static-only; Runtime Skill Audit and MalSkillBench — actual behavior research. Actual behavior evals required; no Tier 2/3 or mandatory paid APIs. Metrics: recall, precision, false COMPLETE, evidence accuracy, coverage, stale evidence, source integrity, resume, tokens and time. No opaque aggregate score.

## Research 26 November 2026 — TD17/T13, TD04, Project Audit, Repository Workflow

- **TD17:** [Codex Windows sandbox source](https://github.com/openai/codex/blob/main/codex-rs/windows-sandbox-rs/src/sandbox_utils.rs) injects safe.directory using GIT_CONFIG_COUNT/KEY/VALUE. [Upstream issue #63115](https://github.com/openai/codex/issues/63115) describes ten Windows Desktop config pairs and missing empty values. This user report does not establish the cause in the specific TESSERA profile. Never remove variables automatically or accept arbitrary config overrides; diagnose names, then study a native safe host interface. Do not publish keys/values or security state. Actual acceptance remains open.
- **T13:** [Codex hooks](https://learn.chatgpt.com/docs/hooks) and experimental [dsh-hooks-codex](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/experimental/hooks-codex/README.md) suggest researching one portable Stop/PreToolUse/PostToolUse protocol; experimental compatibility is not release enforcement. Test permissions, errors, repeated invocation and missing hooks; retain independent Git/CI gate. Do not enable plugins automatically.
- **TD04:** [git cat-file --batch](https://git-scm.com/docs/git-cat-file) reduces read subprocesses. Disposable Linux fixture, Git 2.47.3, 256 unique blobs, 74050 bytes, three repetitions: median individual cat-file 0.50815 s, batch 0.01379 s (~36.8x read only). Exact bytes, order, type, length and SHA-1 checked 256/256. Prototype without Gitleaks, not a CI benchmark. Next candidate: bounded chunks, framing/OID/size/EOF and deadline validation; retain inventory recheck and host/container parity. [GitHub cache security](https://docs.github.com/en/actions/concepts/workflows-and-actions/dependency-caching): caches are untrusted; never inherit PR PASS; no verdict cache before trust-model review.
- **Project Audit:** [SARIF 2.1.0](https://docs.oasis-open.org/sarif/sarif/v2.1.0/sarif-v2.1.0.html) offers fingerprints/baselineState. Separate finding identity and evidence freshness; matching is not revalidation. DELTA must invalidate changed dependencies, config, analyzer version and incomplete scope; absence is not proof of remediation. [Codex Security workflow-routing evals](https://github.com/openai/codex-security/blob/main/evals/workflow-routing/README.md) illustrate fresh-session skill loading tests; compare with no-skill fixtures and record false activation and actions, not just model answers.
- **Repository Workflow:** [git worktree](https://git-scm.com/docs/git-worktree) supports machine-readable list --porcelain, lock and prune dry-run. Include in future read-only inventory; do not delete based solely on ancestry after squash; compare accepted blobs/patch, open PRs and local use. [Git refs API](https://docs.github.com/en/rest/git/refs?apiVersion=2022-11-28) documents ref deletion; current connector lacks DELETE, owner action after worktree check. Do not delete Actions history for cosmetic counts.

Results: primary sources reviewed; batch prototype and isolated diagnostics checks executed; no external dependencies, host configuration or security gates changed. Full CI and product acceptance required.

## 26 November 2026 — conservative DELTA invalidation and worktrees

- [Bazel Skyframe](https://be.bazel.build/designs/skyframe.html): registered dependency graph and reverse transitive closure of changes. Reuse the principle, not a Bazel dependency; incomplete graph or changed context requires full re-audit. Do not implement change pruning yet: a check result is not evidence when an untracked input changed. The delta_plan.py candidate runs no audit and transfers no PASS; 14/14 isolated tests, 1500-node chain. Live acceptance open.
- [in-toto validation model](https://github.com/in-toto/attestation/blob/main/docs/validation.md): trusted signer, statement/predicate type and subject digest are separate verification steps. A level V Project Audit research direction; a digest or source name alone cannot establish authenticity.
- [Git worktree](https://git-scm.com/docs/git-worktree): porcelain -z, bare/detached/locked/prunable. Branch deletion after squash requires checking unique changes, local occupancy and PR status; prunable is not permission to delete a worktree. First a separate read-only NUL-framed parser without publishing paths/lock reasons, double observation and rejection of unknown formats, then GitHub checks. Do not automate deletion at this stage.

## 26 November 2026 — DELTA correctness and skill evaluation

- [Riker, USENIX ATC 2022](https://www.usenix.org/conference/atc22/presentation/curtsinger): incremental correctness depends on dependency completeness. For DELTA, check implicit inputs and negative cases; a matching digest does not authorize PASS reuse.
- [SkillsBench](https://arxiv.org/abs/2602.12670) and [SWE-Skills-Bench](https://arxiv.org/abs/2603.15401): paired trials with/without skills, deterministic criteria. For P01–P08, E01–E20, RW01–RW20 measure outcomes, activation errors, authorization violations, time and budget. Published results not reproduced; no new dependencies.
- [git range-diff](https://git-scm.com/docs/git-range-diff): human review of patch series, not a stable machine interface or proof of squash equivalence. Cleanup needs exact SHA, content comparisons and worktree inventory.
