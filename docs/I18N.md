# Языковая политика TESSERA

[**Русский — оригинал**](I18N.md) | [English — translation](I18N.en.md)

## Главный принцип

**Вся публичная документация сначала создаётся и проверяется на русском языке.** Английская версия — полный перевод, а не сокращённое резюме. При расхождении приоритет имеет русский оригинал; расхождение требуется исправить.

## Имена файлов

- `README.md` — русский оригинал; `README.en.md` — английский перевод.
- Аналогично для `AGENTS.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md` и `docs/*.md`.
- В каждом навыке `skills/<slug>/README.md` — русский, `README.en.md` — английский.
- Для Agent Skills техническая точка входа **только** `skills/<slug>/SKILL.md` на русском языке. Перевод инструкций размещается в `skills/<slug>/references/SKILL.en.md`. Нельзя создавать второй `SKILL.md` в подкаталоге перевода и выдавать его за отдельный навык.
- Остальные справочные `references/*.md`, написанные на русском, получают парный `*.en.md`.
- `LICENSE` и машинные файлы (Python, CI, YAML-шаблоны GitHub) сохраняются в формате, принятом их экосистемой; не требуется удваивать исполняемые файлы.
- Для Pull Requests и Issues разрешены двуязычные шаблоны с русским текстом первым; их отдельные переводы не обязательны для работы GitHub. При расширении публичного руководства — приложите английский вариант.

## Правила изменений

1. Сначала изменить русский оригинал.
2. Затем в том же изменении полностью синхронизировать английский перевод: смысл, ограничения, команды, пути, ссылки, версии и статусы.
3. Вверху каждого документа добавить переключатель «Русский | English».
4. Не переводить технические идентификаторы, команды, пути, имена файлов и коды состояний. Не публиковать частные локальные пути.
5. Писать коммиты, аннотации тегов, релизы и основные отчёты на понятном русском языке; английский текст можно добавить отдельной секцией, **после** русского.
6. Проверить `python tools/check_translations.py` и остальные тесты. Наличие пары файлов проверяется автоматически, точность смысла требует человеческой проверки.

## Ограничение автоматической проверки

CI обнаруживает отсутствующие пары файлов, осиротевшие английские документы и отсутствие языкового переключателя. CI **не доказывает** качество и актуальность перевода. Проверка смыслового соответствия обязательна при ревью.
