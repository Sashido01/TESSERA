# Дорожная карта TESSERA

[**Русский — оригинал**](ROADMAP.md) | [English — перевод](ROADMAP.en.md)

**Назначение:** поэтапное развитие единого публичного каталога Agent Skills с проверяемым ядром микроверсионности и небольшими адаптерами для разных агентных систем.

**Версионирование самой TESSERA:** обязательная последовательная микроверсионность по [политике версий](VERSIONING.md). Дорожная карта не назначает версии будущим этапам заранее и не требует фиктивных коммитов. `.99` — релизный рубеж после готовности и проверок; незавершённая работа продолжается `.100+`.

**Ограничения, утверждённые владельцем (23.11.2026):** не добавлять сторонние менеджеры распространения навыков; не использовать NVIDIA SkillEvaluator Tier 2 или Tier 3; не вводить обязательные платные AI API. Официальный GitHub CLI — предпочтительное распространение после проверки; Python-установщик остаётся минимальным офлайн-резервом. Русские документы — оригиналы, полные английские переводы обновляются в том же изменении. Подробно: [зависимости и границы](DEPENDENCIES.md).

## Правила статусов

- `COMPLETE` — есть проверяемые файлы, реальные результаты необходимых тестов и указанные ограничения.
- `PARTIAL` — часть реализована, хотя обязательные критерии ещё не выполнены.
- `NOT_VERIFIED` — код/инструкция подготовлены, но исполнение в целевом окружении не проверено.
- `NOT_STARTED` — выполнение этапа не начато; само описание в дорожной карте не доказывает реализации.
- `BLOCKED` — обнаружен конкретный препятствующий фактор с зафиксированной причиной.

Текущее состояние ниже основано на исходниках GitHub и успешном Linux GitHub Actions для TESSERA `v0.0.21`. Это **не** является доказательством работы во всех агентных клиентах и на локальном Windows.

## Приоритетные этапы T08–T17

Этапы предлагается выполнять маленькими проверяемыми задачами, с отдельной микроверсией для каждого действительно завершённого изменения. Открытие следующего независимого этапа возможно, если предыдущий заблокирован и нет скрытой зависимости.

### T08 — Git, права и защита публикации

**Приоритет P0 · Статус PARTIAL (серверная защита активна; отдельные негативные сценарии NOT_VERIFIED).** Rulesets `Protect main` и `release tags` активированы. Pull Request #1 подтвердил блокировку неверной версии, успешное слияние исправленной версии и выпуск аннотированного `v0.0.6`. [Инструкция и доказательства](GITHUB_SECURITY.md). Подготовить проверяемые GitHub Rulesets: обязательный CI перед изменением защищённой ветки, запрет force-push и удаления истории, ограничения на изменение/удаление опубликованных тегов, минимальные полномочия Actions. Проверить поведение для обычного PR, администратора, автоматического тегирования и конкурирующих обновлений. Изменение настроек репозитория — отдельное разрешённое действие; недоступные в текущем подключении права фиксировать как BLOCKED, не заявлять о готовой защите.

**Приёмка:** правило реально действует в GitHub; попытка обойти необходимые checks или изменить опубликованный тег отклоняется. Сохранить ссылки на настройки и проверенные результаты.

**T08.01 (CI-обслуживание):** обновлены закреплённые GitHub Actions до поддерживаемого Node.js 24, добавлена обязательная проверка точных SHA и отрицательные тесты отката. [Отчёт и таблица SHA](GITHUB_SECURITY.md). Эта подзадача требует подтверждённого CI `main` и аннотированного тега после слияния. Реальная проверка административного обхода и удаления тегов по-прежнему NOT_VERIFIED; общий T08 — PARTIAL.

### T09 — Независимое ядро Release Core

**Приоритет P0 · Статус PARTIAL (реализованы T09.01–T09.10; живая приёмка подписанного ZIP T09.10 — COMPLETE).** Реализованы [локальный инспектор](RELEASE_CORE.md), [Preflight](RELEASE_PREFLIGHT.md), [remote](RELEASE_REPORT.md), [завершённый CI](RELEASE_CI.md), [метаданные GitHub Release](RELEASE_PUBLICATION.md), [байты assets](RELEASE_ASSETS.md), [проверка provenance](RELEASE_PROVENANCE.md) и [доверенная сборка исходного пакета каталога](TRUSTED_BUILD.md). В T09.08 ZIP пакета формируется детерминированно из точного Git-коммита; отдельный workflow может **вручную на подтверждённом теге** создать GitHub/Sigstore attestation и передать пакет через GitHub Actions Artifacts. Автоматической публикации GitHub Release нет. Реальная подпись и сквозная проверка исходного ZIP подтверждены для v0.0.21. Готовность исполняемых приложений и параллельная координация агентов остаются NOT_VERIFIED. Дальше разделить `inspect`, `next`, `preflight`, `verify-build`, `tag`, `verify-tag`, `verify-remote`, `report`. Читать реальные команды тестов и сборки только из конфигурации целевого проекта. Проверять соответствие версий и CHANGELOG, точный релизный SHA, отсутствие лишних изменений, права на запись и обязательный аннотированный тег. Различать состояния WORKING, PREPARED, VALIDATED, TAGGED, RELEASED, BLOCKED. Не считать Git-тег доказательством успешной сборки или публикации.

**T09.09:** добавлен [офлайн-верификатор ZIP](CATALOG_VERIFICATION.md), проверяющий содержимое пакета без распаковки. Он подтверждает внутреннюю целостность относительно MANIFEST.json и независимых параметров версии/коммита, но не заменяет GitHub attestation. Проверка подписанного ZIP v0.0.21 выполнена отдельно в T09.10. Общий статус T09 — PARTIAL.

**T09.10 — реальный сбой и исправление (24.11.2026):** Запуск [45347443989](https://github.com/Sashido01/TESSERA/actions/runs/45347443989) на аннотированном `v0.0.19` завершился FAILURE: тесты PASS, упаковка `PACKAGE_RUNTIME_FILE_INVALID`, подпись/артефакт SKIPPED (0). Причина — создаваемый тестами `__pycache__` внутри `scripts/`. Исправление T09.10.01: запрет записи bytecode в CI и signing, отдельная сборка после тестов в проверочном CI, строгий allowlist без ослабления, негативные регрессионные тесты. Исправление выпущено в 0.0.21. Источник: [TRUSTED_BUILD](TRUSTED_BUILD.md).

**T09.10 — COMPLETE (24.11.2026):** на аннотированном теге `v0.0.21`, commit `0c83ae9ef119a0cfc9d07c83dbae91e5d026e407`, [signing run 45348928593](https://github.com/Sashido01/TESSERA/actions/runs/45348928593) завершился SUCCESS. [Attestation 71489191](https://github.com/Sashido01/TESSERA/attestations/71489191), [Actions Artifact 14898798605](https://github.com/Sashido01/TESSERA/actions/runs/45348928593/artifacts/14898798605). Независимое скачивание: ZIP 105849 байт, SHA-256 `55db489f0219739e9296fc941fa51fa58d23c3277878fe5e3a352642947eeb73`, 17 файлов манифеста проверены. Владелец на Windows независимо подтвердил этот SHA-256 и `gh attestation verify` официальным `gh 2.105.0`: `Verification succeeded!`, одна аттестация соответствует SLSA v1, точному репозиторию, commit, тегу, signer workflow, OIDC issuer и GitHub-hosted runner. Подтверждение владельца основано на предоставленном выводе CLI; ZIP и хеш отдельно проверены. `SIGNED_ARTIFACT=PASS` **только для этого файла версии 0.0.21**. [Issue #11](https://github.com/Sashido01/TESSERA/issues/11) имеет подтверждённые критерии приёмки. GitHub Release не создавался; интеграция Actions Artifacts в Release Core, проверки приложений и конкурентные релизы остаются незавершёнными.

**Приёмка:** отрицательные тесты на отсутствующий, легковесный, неверно привязанный или повторный тег; проверка старого релиза без сравнения исключительно с текущим HEAD; воспроизводимое восстановление после сбоя. Релиз с ошибками обязательных проверок остаётся BLOCKED.

### T10 — Официальный GitHub CLI как распространение

**Приоритет P1 · Зависит от T08 по вопросам безопасной публикации · Статус PARTIAL (T10.01 — COMPLETE; T10.02 — проверка в CI).** Реализована [изолированная проверка локальной установки официальным `gh`](GH_SKILL_INSTALL.md) с SHA-256 закреплённой версией, обнаружением через `gh skill list`, проверкой неизменности исходников и защитой от перезаписи. Флаги `--from-local` и `--pin` несовместимы, а локальная установка может перезаписать файлы без `--force`: это учтено в стратегии отказа. T10.02: отдельная проверка на реальном gh 2.105.0 по полному ref аннотированного тега v0.0.22 и commit SHA, сверка Git tree, метаданных и байтов, pinned update --dry-run, отрицательная повторная установка; завершение только по GH_SKILL_REMOTE_PIN_PASS. Далее остаются применённые обновления и ограничения многопрофильного монорепозитория. Исходный план: Проверить в изолированном окружении совместимость доступной версии `gh skill` с TESSERA: обнаружение, просмотр, установка, `--pin` по тегу и SHA, `--dir`, обновление, DRY-RUN, поведение монорепозитория с отдельными тегами навыков. Применять точную подтверждённую версию GitHub CLI; учитывать preview-статус интерфейса.

**Приёмка:** навыки устанавливаются воспроизводимо из GitHub посредством официального GitHub CLI, локальные изменения пользователя не теряются при обновлении, привязка к исходной Git-ревизии проверяема. Собственный Python-установщик остаётся минимальным офлайн-вариантом и вариантом для нестандартных каталогов.

### T11 — Эталонный стандарт Agent Skills

**Приоритет P1 · Статус PARTIAL (T11.01 и T11.02 — локальная проверка).** Добавлен [официальный dry-run GitHub CLI](GH_SKILL_PUBLISH_DRY_RUN.md) версии 2.105.0, закреплённой SHA-256, на временном каталоге без remote и токенов. Его реальный CI PASS необходим для COMPLETE этой подзадачи. Действительная проверка публичных тем, GitHub Release и функций публикации остаётся NOT_VERIFIED. **Исходный статус:** Встроена отдельная проверка формата `skills-ref` из зафиксированного полного SHA upstream с хешированными зависимостями в CI; фактический CI PASS обязателен для статуса COMPLETE у T11.01. Reference-библиотека обозначена авторами как демонстрационная, поэтому собственные проверки TESSERA сохранены. Локальный `gh skill publish --dry-run` включён в CI; без реального успешного запуска результат NOT_VERIFIED. Проверка с remote и правами публикации отдельно NOT_VERIFIED. Первоначальный план: встроить официальную проверку формата `skills-ref` и проверить публикационную пригодность через `gh skill publish --dry-run`. Закрепить проверенные версии инструментов. Собственный валидатор оставить только для специфики TESSERA: независимые версии, русский оригинал, английские переводы, запрет приватных путей, теги и безопасность.

**Приёмка:** искажённые YAML/frontmatter, неверные имена и повреждённые навыки дают ошибку CI; dry-run не публикует новый релиз.

### T12 — Бесплатная оценка NVIDIA SkillEvaluator

**Приоритет P1 · Зависит от T11 · Статус NOT_STARTED.** Изолированно исследовать **только Tier 1**, проверку качества/совместимости без обязательного LLM API. Измерить фактические зависимости, время выполнения, отчёты, коды выхода и ложноположительные предупреждения на TESSERA. Отдельно проверить, какие агенты действительно поддерживаются анализатором; для DeepSeek Harness оставить собственную матрицу.

**Приёмка:** воспроизводимый Tier 1 отчёт (формат результата, окружение, выявленные проблемы); зафиксированы затраты CI и поведение без платных ключей. Tier 2, Tier 3 и обязательные платные API **не подключать** ни при каких условиях этого плана.

### T13 — Тонкие адаптеры Codex и DeepSeek Harness

**Приоритет P1 · Зависит от T09 · Статус NOT_STARTED.** Сохранить одно ядро; адаптеры только передают события/контекст, запускают общий preflight/verifier и блокируют заведомо неподтверждённый релиз в пределах возможностей платформы. Для Codex исследовать проектные инструкции и реальные Hooks, для Harness — нативные события/совместимые плагины. Не устанавливать сторонние плагины автоматически.

**Приёмка:** в реальных версиях обеих систем проверены загрузка, вызов ядра, ошибка при отсутствии тега, сохранность чужих изменений и точность итогового отчёта. Неподдерживаемые события честно обозначены NOT_VERIFIED или BLOCKED.

### T14 — Тонкие адаптеры Claude Code и Hermes

**Приоритет P1 · Зависит от T09 · Статус NOT_STARTED.** Реализовать аналогичный интерфейс адаптеров; для Claude использовать документированные механизмы проектной конфигурации и Hooks; для Hermes изучить фактический безопасный механизм доверия и событий. Где нет подтверждённого блокирующего хука, опираться на независимую Git/CI-проверку.

**Приёмка:** подтверждена работа навыка в конкретных установленных версиях, положительные и отрицательные тесты релиза, отсутствие самовольной настройки доверия.

### T15 — Одновременная работа нескольких агентов

**Приоритет P1 · Зависит от T09, T13–T14 · Статус NOT_STARTED.** Единый источник версии, координация релизов и защита от гонок между несколькими агентами, worktree и CI. Повторная проверка HEAD и ссылок Git до записи, идемпотентность, ограниченные повторы, безопасное восстановление после частичной операции. Не передвигать опубликованные теги.

**Приёмка:** конкурентные тесты не приводят к дублирующимся номерам, перезаписи тегов или потере чужой работы; при невозможности синхронизации релиз блокируется с понятной причиной.

### T16 — Независимые версии нескольких навыков

**Приоритет P2 · Зависит от T09–T11 · Статус NOT_STARTED.** Определить источник версии каждого навыка, правила тегов вида `<skill>/vX.Y.Z`, поиск установленных ревизий, обратную совместимость и миграции. Отдельно от версии каталога TESSERA. Не вводить общий runtime для всех навыков как обязательное условие.

**Приёмка:** два навыка меняются и выпускаются независимо, не конфликтуют тегами, корректно устанавливаются и обновляются из одного репозитория.

### T17 — Проверяемые публичные релизы

**Приоритет P2 · Зависит от T08–T12 и T16 для независимых выпусков · Статус NOT_STARTED.** Подготовить версии пакетов и проверяемые GitHub Releases при реальной необходимости. Исследовать неизменяемые выпуски GitHub, контроль SHA и цепочку происхождения. Не публиковать GitHub Release автоматически только из-за рабочего микрокоммита.

**Приёмка:** для реально выпущенной версии можно установить точный исходный Git SHA, аннотированный тег, результаты CI, архив/пакет (если существует) и доступность опубликованного выпуска.

## Общие условия завершения каждой задачи

1. Реально выполненное изменение, его основание и границы.
2. Следующая законная микроверсия TESSERA и конкретный коммит с русским сообщением.
3. Согласованная русская документация и полный английский перевод в том же коммите.
4. Точные команды тестов, результат PASS/FAIL/SKIP и неподтверждённые платформы.
5. Аннотированный Git-тег по правилам TESSERA; для полноценных релизов обязательна проверка привязки к релизному коммиту.
6. Обновлённая дорожная карта и понятный отчёт COMPLETE / PARTIAL / BLOCKED / NOT_VERIFIED.
7. Отсутствие частных рабочих путей, секретов, форсированного изменения Git-истории или несанкционированной публикации.

## Ключевые принципы

- Не строить собственную копию менеджера GitHub CLI, если официальный механизм решает задачу.
- Не вводить сторонние менеджеры навыков в зависимости, резервную установку или CI; в публичной документации описывать только принятые инструменты.
- Не использовать NVIDIA SkillEvaluator Tier 2/3, платные режимы и обязательные платные AI API.
- Не считать наличие SKILL.md доказательством его автоматической активации.
- Не делать четыре независимых ядра микроверсионности: один контроллер, небольшие адаптеры.
- Для неизвестного или неподтверждённого поведения писать NOT_VERIFIED, а не угадывать.
