# UP02 — локальный план установки и обновления

[**Русский — оригинал**](PROFILE_UPDATE_PLAN.md) | [English — перевод](PROFILE_UPDATE_PLAN.en.md)

**PARTIAL, отдельный кандидат.** `python -B tools/profile_plan.py --profile <absolute-skills-root> --stage <absolute-new-stage-root> --baseline <absolute-old-stage-root> --resolution <absolute-resolver-json>`. Все корни должны существовать, быть раздельными и доверенными. Baseline опционален для отсутствующих и идентичных навыков; существующее отличающееся дерево требует независимой чистой копии старой версии, не копии изменённого рабочего каталога. Resolution задаёт один, несколько или все навыки и intent install/update; сам JSON не является полномочием. Не выполнять этот код в непроверенном checkout.

План ничего не записывает, не вызывает Git/gh, не перемещает файлы и не исполняет навыки. Проверяет только выбранные деревья, включая скрытые/дополнительные записи и modes, хеширует фактические bytes (включая gh frontmatter) и повторно сверяет наблюдавшуюся identity. Для обнаружения alias перечисляет ограниченный список имён непосредственно в корнях, не открывает содержимое соседних навыков. При отличающейся структуре не открывает неожиданные файлы рабочего навыка. BLOCKED при links/reparse/alias, special files, hardlinks, crossing device, overlapping roots, local changes, missing baseline, non-advancing version. PLAN_INSTALL / PLAN_UPDATE / SKIP_MATCHING_STAGE — только относительно предоставленных копий, не доказательство upstream.

Ограничения: 512 записей/дерево, 16 MiB/дерево, 2 MiB/file, depth 8, 4096 direct entries/root, 128 MiB attempted reads и 60 s cooperative budget; не жёсткий I/O timeout или sandbox. Стабильная доверенная файловая система; persistent changes checks не гарантируют защиту от TOCTOU, bind mount, NTFS aliases/ACL или конкурентных writers. Никакой автоматической авторизации: apply_authorized false, source_authenticity NOT_VERIFIED, exclusive_access NOT_VERIFIED, snapshot_atomic false. Сторонний gh metadata/источник проверяются независимо; Git tree и stage fingerprint — разные идентификаторы. Нельзя копировать local edits в baseline, чтобы получить PLAN_UPDATE. Следующий рубеж: независимо связать каждый staging snapshot с точным GitHub tag/tree и gh metadata, crash-safe journal, no-clobber swap и rollback, native Windows/Linux, реальный клиент.

12/12 focused Linux tests PASS (0.052 s, Python 3.13.5), synthetic actual files; exact source e7a2bf4d8e47b12a3dc7561c78a8521c5d0129ac, tests 5b3a5434a538fae82dfbd701f8f469880bf7ab39. Native/full CI pending. Отдельная ветка зависит от PR #101, общая версия пока не назначена. UP01/UP02/G03/G04/G05 остаются PARTIAL.

## UP02.01 — доказательство raw tree (кандидат)

`python -B tools/skill_tree.py --stage <absolute-raw-stage-root> --resolution <absolute-resolver-json>` восстанавливает объекты Git SHA-1 blob/tree непосредственно из фактических raw bytes, с порядком сортировки каталогов Git; требует точного ожидаемого дерева и VERSION. Все текущие опубликованные файлы навыков mode 100644, сверено с GitHub tree inventory. Пустые каталоги, неожиданный executable mode, ссылки, alias и несовпадающие байты отклоняются. За один проход по содержимому вычисляется тот же stage SHA-256 snapshot fingerprint, что и в profile_plan; повторно проверяются все наблюдавшиеся записи между навыками. Не вызывает Git/gh, не пишет, не исполняет навыки, не использует учётные данные. Resolution должен быть независимо удостоверен и актуален; совпадение предоставленного OID не подтверждает live tag или attestation. gh-injected SKILL.md не совпадает с raw tree и намеренно отклоняется; смысловая проверка фактических gh metadata и связывание старого/нового проверенных staging с apply открыты. Новая runtime dependency не введена. 10/10 изолированных Linux-тестов PASS (0.050 s), включая actual git write-tree fixture; совместно UP02 22/22 PASS (0.086 s). Exact source 9c3b1d121b52b754364c932d6ba17f3fdfdb0d5d, tests 9e2a3ed7d9b0840420be0865fc64324386b1309b. Native Windows и actual gh NOT_VERIFIED. Не production updater.

Исходники upstream gh v2.105.0 подтверждают: RecordInstall вызывается даже при явном staging directory, отдельно от записи файлов навыка; lockfile использует user home. Значит staging с настоящим HOME может изменить общие lock metadata до безопасной замены. Для реальной приёмки использовать отдельно разрешённый изолированный fixture home, не обходить ограничения выдуманной подменой среды. Сверка lockfile после безопасного update — отдельное открытое требование. [Installer source](https://github.com/cli/cli/blob/v2.105.0/internal/skills/installer/installer.go), [frontmatter source](https://github.com/cli/cli/blob/v2.105.0/internal/skills/frontmatter/frontmatter.go).

## Дополнительная проверка стабильности плана

После всех выбранных операций повторно сверяются ordinary roots, alias observations, все метаданные просмотренных деревьев (предки до потомков) и явно отсутствующие цели. Не полагаться только на mtime родительского каталога. Windows cross-method stat/fstat сравнение использует сопоставимые поля с birthtime, same-method сохраняет mode/ctime/attributes; reparse/zero inode блокируются. 3 новых regression methods: mutation первого stage после обработки второго, появление ранее отсутствующей цели при синтетически неизменном root stat, Windows ctime/attribute simulation. Combined isolated Linux 25/25 PASS (0.101 s). Exact profile_plan 9b23c5177b85fae81e88752a95ff10fdb87c7c9e, tests ee39642039440c38ff953e6d73b8d4a212c0f729; raw tree source/test unchanged. Native CI и реальный gh открыты; это не atomic, не разрешение на apply, не гарантия эксклюзивного доступа.
