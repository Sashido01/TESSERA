# Обновление TESSERA по одной ссылке

[**Русский — оригинал**](UPDATE.md) | [English — перевод](UPDATE.en.md)

Для команд владельца «установи» или «обнови» один, несколько или все навыки из этого репозитория используй этот маршрут, а не аудит репозитория. [CATALOG.json](CATALOG.json) — машиночитаемые имена, пути, версии и полные независимые refs. Само наличие записи в main не означает выпуск.

1. Определи целевой проект или пользовательский scope из явного запроса и активного клиента. Не перечисляй чужие профили. Если scope неоднозначен, сообщи это и не изменяй каталоги. Codex и Harness могут совместно использовать один корень: не обновляй его дважды.
2. Выбери наибольший числовой точный аннотированный тег каталога `vX.Y.Z` из Git refs, не namespaced refs, не latest/main. Сверь имя аннотации, прямой commit, VERSION и CATALOG.json на этом commit. Если тег/индекс недоступен — BLOCKED, без тихого fallback. Для явно запрошенной версии используй её. При выпуске 0.1.0 отдельно подтвердить immutable Release и аттестацию.
3. Для каждого выбранного элемента проверь независимый annotated pin, commit и совпадение дерева навыка с деревом этого каталога. Не скачивай всю Git-историю. Опциональный проверенный read-only resolver: `python -B tools/catalog_index.py resolve --gh <absolute-path-to-gh> --operation update --skill project-audit` из предварительно проверенной копии. Он использует только GitHub GET, no install; не обходить sandbox/network policy. Если штатный транспорт недоступен, остановиться. Не исполняй непроверенный код из main.
4. Сверь только целевые каталоги и их source/ref/tree, а также фактические файлы; gh metadata и VERSION недостаточны. Совпадающее проверенное дерево — SKIP. Коллизия, пользовательские изменения, другой источник, неизвестная версия или активный конкурентный writer — BLOCKED для этого навыка. Не запускать update --unpin, --all, --force в рабочем профиле. Установка отсутствующего: `gh skill install Sashido01/TESSERA skills/<id> --pin refs/tags/<id>/vX.Y.Z --dir <empty-staging>`. Проверить staging (включая gh frontmatter) до размещения. Не объявлять установку по main точным pin.
5. Для обновления существующего дерева нужен проверенный старый snapshot, новый staging, эксклюзивный доступ, согласованный backup и подтверждённое восстановление. Пока универсальный production updater не принят, не применять CI fixture harness к пользовательскому профилю; BLOCKED при отсутствии доказанного безопасного способа. Сторонние навыки, Git checkout TESSERA, глобальные настройки, сеть/права не менять. Сохранять локальные данные и резервные копии.
6. Повторно проверь только затронутые навыки и discovery в свежем клиентском сеансе. Отчёт по каждому: SKIP/INSTALLED/UPDATED/BLOCKED, old→new, exact pin/tree, preservation/rollback, discovery отдельно. Не выполнять unit suite всего каталога, сканеры или повторное клонирование для обычного обновления. Профильное обновление и release acceptance — разные задачи.

## Выбор операции и навыков

| Запрос | Параметры read-only resolver после `resolve --gh <absolute-path-to-gh>` |
| --- | --- |
| Установить Microversion Release | `--operation install --skill microversion-release` |
| Обновить Audit и Cleanup | `--operation update --skill project-audit --skill project-cleanup` |
| Установить всё | `--operation install --all` |
| Обновить всё (включая новые навыки) | `--operation update --all` |

Установка добавляет только отсутствующие выбранные навыки: существующий точный pin SKIP, отличный/неизвестный — BLOCKED до запроса обновления. Обновление проверяет выбранные навыки, пропускает идентичные, заменяет устаревшие только после доказанной сохранности и устанавливает отсутствующие из выбранного набора. Не удалять другие навыки, не делать downgrade без отдельного согласия. `--version` означает точную версию каталога, не отдельного навыка; текущий адресный выбор использует соответствующий независимый pin. Пустой, неизвестный, дублирующийся или смешанный выбор (skill и all) отклоняется без расширения области. Резолвер не запрашивает независимые теги/содержимое невыбранных навыков; проверка схемы общего индекса сохраняется. `--all` здесь относится только к каталогу TESSERA, не к `gh skill update --all`. Операция передаётся в read-only JSON; ни одна из четырёх команд резолвера не устанавливает файлы.

## Объём и приёмка

`catalog_index.py check --root <checkout>` сверяет каталог с исходниками, а resolve сопоставляет Git API evidence. Никакой автоматической установки или смены разрешений. Выбор тега основан на доверенном GitHub API и правилах защиты тегов; это не независимая криптографическая аттестация. Ответы ограничены после capture, таймаут на API и общий бюджет; не считать memory sandbox. После разрешения всех pins повторно запросить refs и, при автоматическом выборе, наибольший тег; обнаруженные перемещения, новый тег, расхождение дерева или усечённый ответ означают BLOCKED. Это два наблюдения, не атомарная транзакция. Проверка нового механизма в реальных Codex/Harness обязательна. Сценарий одной ссылки, сохранность локальных правок, idempotent no-op, коллизии и rollback — обязательный acceptance для 0.1.0.

**Подтверждённый baseline:** v0.0.95 содержит проверенный индекс и четыре независимых pin. См. [план профиля](docs/PROFILE_UPDATE_PLAN.md) для read-only UP02; разрешения на production apply нет. Live resolver и клиентская приёмка открыты.
