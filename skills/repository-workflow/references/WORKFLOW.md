# Параллельная разработка

[**Русский — оригинал**](WORKFLOW.md) | [English — перевод](WORKFLOW.en.md)

## Профили
LOCAL: Git и локальные проверки, существующая дорожная карта/реестр. GITHUB: нативные Issues и зависимости, PR, Actions, Rulesets и при необходимости Projects. SINGLE/MULTI: один переключающийся агент или несколько изолированных исполнителей. MONOREPO: независимые компоненты и общий интеграционный слот. BOOTSTRAP/EXISTING: новая настройка или бережное улучшение существующего проекта.

## Цикл
Инвентаризация → обработка завершившихся проверок → выбор независимой задачи → работа в ограниченной области → быстрые проверки → очередь интеграции → проверка на актуальной базе → обязательная приёмка → релиз по политике проекта → контроль долга. Начинай с основного проекта, далее каждый компонент; не жди впустую. Порядок внутри потока: блокирующие дефекты, P0, P1, P2. Не назначай задачи сверх мощности исполнителей; не повторяй дорогие проверки для неизменного SHA без причины.

## Ветки и интеграция
Короткоживущая ветка на одну цель; при ошибке исправляй её же. Изолируй worktree и изменяемые ресурсы. Записывай зависимости и области записи; неполный граф означает неопределённость, не гарантированную независимость. Промежуточные коммиты допустимы без номера принятой версии. Слот интеграции один на общий VERSION/CHANGELOG; назначай следующую версию относительно актуального main, затем проверяй точный merge-кандидат. На GitHub используйте правила защиты, строгий CI, squash при согласованной политике, проверку ожидаемого HEAD PR. Нативная merge queue — при доступности; иначе один координатор без обхода правил. Не удаляй незавершённые ветки. Локально обеспечивай эквивалентную последовательность, не добавляй remote автоматически.

## Настройка нового проекта
Сначала план и инвентаризация; не перезаписывай существующие файлы. Согласуй цели, Git, минимальные правила агента, README, журнал задач, штатную проверку и версионирование. GitHub-профиль дополняет это PR, pinned Actions, минимальными правами, required checks, Rulesets и шаблонами. Применяй только необходимые компоненты; переиспользуй штатные конфигурации, не создавай сложную платформу. Проверяй положительные и отрицательные сценарии в тестовом репозитории. Настройки безопасности и сетевые действия — отдельные разрешения.
