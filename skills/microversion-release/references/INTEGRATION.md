# Подключение Microversion Release к мультиагентным системам

[**Русский — оригинал**](INTEGRATION.md) | [English — перевод](INTEGRATION.en.md)

## Единая переносимая основа

Структура навыка `SKILL.md + scripts/ + references/` соответствует соглашению Agent Skills. Нет обязательной зависимости от Codex, DeepSeek Harness, Claude Code, Hermes, MCP, отдельного сервера или сетевой авторизации. Для скриптов проверки нужен Python 3, для тегов Git — установленный Git и соответствующие права.

В разных средах **различаются** папки загрузки навыков, условия обнаружения, доверие к проекту и способ принудительного выполнения. Наличие `SKILL.md` не означает автоматическое исполнение после каждого изменения.

## Минимальные полномочия (LP3)

| Операция | Требуемый доступ и граница |
| --- | --- |
| Расчёт версии | Python, без записи проекта |
| Проверка релизного тега | Чтение выбранного репозитория, доверенный Git |
| Проверки проекта | Только согласованные команды проекта |
| Установка | Явный --apply, запись только нового каталога навыка |
| Коммит и создание тега | Разрешённая запись выбранного репозитория, без изменения существующего тега |
| Публикация | Отдельное разрешение, доверенный remote, минимальный токен |

Поле allowed-tools в [спецификации Agent Skills](https://agentskills.io/specification) экспериментальное и задаёт предварительно одобренные инструменты, а не верхнюю границу разрешений. Не добавляем его ради устранения LP3. Эта таблица описывает намерение, но не устанавливает системный sandbox. Реальные ограничения Codex, Harness и других клиентов нужно проверить отдельно. Хук не заменяет независимую приёмку Git/CI; сбой хука не считается доказательством прохождения проверки.

## Быстрая безопасная установка

Из корня клонированной TESSERA (замените `<project-root>` на каталог целевого проекта):

```bash
python skills/microversion-release/scripts/install.py --platform codex --project-root <project-root>
python skills/microversion-release/scripts/install.py --platform codex --project-root <project-root> --apply
```

Без `--apply` программа **ничего не изменяет** и только показывает путь. С `--apply` копирует целый навык; существующий каталог не перезаписывается, секреты и чужие файлы не затрагиваются.

Варианты: `--platform codex|harness|claude|hermes|shared`. `shared` использует общий для Codex и Hermes проектный каталог `<project-root>/.agents/skills/`. Для нестандартного профиля или других систем задайте явно `--platform generic --target-root <skills-dir> --apply`. Пользовательские установки выполняйте только после проверки активного каталога соответствующей системы.

## Стандартный канал распространения

**Официальный GitHub CLI 2.105.0** прошёл изолированные проверки CI: `gh skill publish --dry-run`, локальная установка, удалённая установка из публичного каталога по полному тегу/commit SHA и staged re-pin/rollback. Это не доказательство установки и активации в реальном профиле агента. Локальная установка может заменить файлы существующего каталога: сначала проверьте назначение, для обновления используйте отдельный staging. Минимальный установщик на Python остаётся офлайн-резервом и отказывается работать при существующем назначении. Подробности каталога доступны в публичном репозитории TESSERA: [GH_SKILL_INSTALL](https://github.com/Sashido01/TESSERA/blob/v0.0.30/docs/GH_SKILL_INSTALL.md).

TESSERA не требует стороннего менеджера навыков. `skills-ref`, NVIDIA SkillEvaluator Tier 1 и статические сканеры относятся к контуру качества разработки, а не к зависимостям среды исполнения. Обязательные платные AI API и оценка Tier 2/3 исключены. Навык содержит собственную [лицензию MIT](../LICENSE.txt); [политика зависимостей каталога](https://github.com/Sashido01/TESSERA/blob/v0.0.30/docs/DEPENDENCIES.md) — дополнительное чтение, а не локальное требование установки.

## Codex (OpenAI)

Проект: `<project-root>/.agents/skills/microversion-release/SKILL.md`. Пользовательский уровень: `<user-home>/.agents/skills/microversion-release/SKILL.md`. Codex находит навыки по описанию или через явный выбор в интерфейсе. Используйте его актуальные механизмы загрузки и, при необходимости, проектный `AGENTS.md` для обязанности применять навык. **Загрузка не гарантирует обязательного тегирования** без независимой проверки Git/CI.

Документация: https://developers.openai.com/codex/skills

### Диагностика TD17 (#81)

В исходной сессии Codex, **без изменения её окружения**, выполните:

```bash
python -B scripts/release_tag.py context
```

Запускайте из каталога установленного навыка или укажите путь к проверенной копии. Команда не запускает Git и не требует корня проекта, ничего не записывает. Сохраните только JSON, код выхода, версию клиента и ОС. GIT_CONTEXT_UNSAFE (код 1) — блокировка; NO_BLOCKING_CONTEXT_OBSERVED (код 0) — отсутствие известных блокирующих имён, не подтверждение безопасности. При блокировке не удаляйте переменные и не обходите policy. Согласуйте с владельцем отдельный запуск проверок в доверенной среде вне агента с сохранением действующих ограничений; результаты такого запуска не доказывают совместимость Codex. Точный контракт передачи доверенного контекста и приёмка в реальном клиенте остаются открытыми.

## Hermes Agent (Nous Research)

Проектный каталог: `<project-root>/.hermes/skills/microversion-release/` **или** общий `<project-root>/.agents/skills/microversion-release/`. Пользовательский профиль по умолчанию использует `<user-home>/.hermes/skills/`, но альтернативные профили необходимо проверять отдельно. По требованиям Hermes проектные навыки **не загружаются из неизвестного репозитория без доверия**; решение о доверии принимайте после просмотра файлов, затем в проекте можно выполнить `hermes skills trust`.

TESSERA также подходит для штатного каталога Hermes (tap):

```bash
hermes skills tap add Sashido01/TESSERA

```

Команды показаны на основании официального синтаксиса Hermes; установка и обнаружение в конкретном пользовательском Desktop/CLI пока **NOT_VERIFIED**. Проверяйте отчёт сканера безопасности и активный профиль.

Документация: https://hermes-agent.nousresearch.com/docs/user-guide/features/skills

## Другие агенты и оркестраторы

Для среды, поддерживающей Agent Skills, используйте `--platform generic --target-root <skills-dir>`. Для платформ без поддержки стандарта нужна отдельная интеграция, читающая `SKILL.md`, предоставляющая модели документацию и вызывающая детерминированный скрипт проверки перед релизом.

Для нескольких агентов, работающих с одним репозиторием: единый источник версии, сериализация коммитов и релизов, повторная проверка HEAD, запрет перезаписи существующих тегов и совместный контроль средствами CI. Модель и Agent Skills сами по себе не являются системой распределённых блокировок.

## Приёмка интеграции

1. Проверить фактическую версию клиента и корневую папку навыков.
2. Установить весь каталог и убедиться, что навык доступен агенту.
3. Проверить вычисление `0.0.99 → 0.0.100` для незавершённой задачи.
4. В **изолированном тестовом репозитории Git** выполнить релиз `0.1.0`: реальные проверки, содержательный коммит, аннотированный тег и `release_tag.py verify`.
5. Убедиться, что отсутствующий/неправильный тег даёт `BLOCKED / RELEASE_NOT_TAGGED`.
6. Отдельно проверить автоматическую активацию, если она требуется: наличие навыка не доказывает её.
7. Не объявлять все платформы проверенными только по одному успешному CI.
