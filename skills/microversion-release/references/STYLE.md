# Стиль коммитов, тегов, CHANGELOG и релизов

## Главный принцип

Текст должен объяснять результат обычному человеку: ясно, конкретно, без выдуманных фактов и преувеличений. Технические термины допустимы, когда они действительно помогают понять изменение.

## Коммиты

**Хорошо**

- «Исправлен повторный запуск приложения после обновления»
- «Добавлена проверка доступности локальной базы перед запуском»
- «Уточнена инструкция восстановления после сбоя»
- «Подготовлена версия 0.2.0 с проверенной сборкой для Windows»

**Плохо**

- «chore: bump to 0.1.24»
- «fix: misc stuff»
- «Выполнены работы в рамках текущего спринта»
- «Обновлена документация и оптимизированы процессы»

Первая строка — короткое самостоятельное сообщение без точки. Если изменение сложное, добавьте 2–5 предложений: зачем понадобилась правка, какие части затронуты, как результат проверен. Не заявляйте то, чего не проверяли.

## Теги

Имя Git-тега машинное: `v0.1.24`. Для нескольких навыков в одном репозитории допустимы пространства имён, например `microversion-release/v0.1.24`. **Аннотация** описывает реальное изменение:

- «Версия 0.1.24 — исправлен повторный запуск приложения»
- «Релиз 0.2.0 — устойчивый запуск и восстановление после ошибок»

Создавайте аннотированные теги на проверенных коммитах; никогда не передвигайте уже опубликованные.

## CHANGELOG

### 0.1.24 — Исправлен повторный запуск

**Что изменилось:** конкретное изменение, подтверждённое исходниками и проверками.

**Как проверено:** фактическая команда, окружение и результат. Если тест не проводился, прямо пишите «Не проверено».

**Ограничения:** непроверенные платформы и сценарии. Не утверждайте, что ограничений нет, если это неизвестно.

## Релиз

### Версия 0.2.0 — Более надёжный запуск

**Что нового:** реальные изменения для пользователя.

**Что исправлено:** конкретные ошибки и подтверждённый результат.

**Как проверяли:** команды, платформы и исход тестов.

**Установка и обновление:** инструкция только при реально доступном пакете.

**Что пока не проверено:** неизвестные сценарии.

## Что не нужно путать

- Версия не доказывает качество.
- Git-тег не равен собранному приложению.
- Запись CHANGELOG не равна опубликованному GitHub Release.
- Артефакт существует лишь тогда, когда реально создан и проверен.

## Работа после .99

Трёхзначный PATCH — обычная рабочая микроверсия, а не «ошибка» или «неудача». Коммит `0.0.100` должен говорить о сделанной работе, а не о переходе через 99. После завершённого и проверенного изменения возможен релиз `0.1.0`. Если работа закончилась только на `0.0.107`, не называйте `0.0.100` финальным коммитом и не выпускайте релиз раньше.
