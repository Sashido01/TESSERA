# Microversion Release

[**Русский — оригинал**](SKILL.md) | [English — перевод](references/SKILL.en.md)

## Назначение и требования

Единая процедура для Codex, Harness, Claude Code, Hermes и других агентов, совместимых с Agent Skills. Не зависит от модели, провайдера или ОС. Нужны целевой репозиторий Git, его политика версий и проверки; Python 3 — для скриптов. Установка: [INTEGRATION.md](references/INTEGRATION.md).

## Ограничения и полномочия

Работай только с явно выбранным проектом. Чтение Git и расчёт версии сами по себе не разрешают запись. Коммиты, теги и публикация требуют соответствующего разрешения и соблюдения правил проекта; публикация разрешается отдельно. Не изменяй установленный навык, настройки безопасности, память агента или чужие файлы. Не обходи проверки, не передвигай теги, не выполняй принудительную отправку Git. При конфликте полномочий сообщи BLOCKED.

Минимальный доступ: чтение выбранного проекта, вычисление версии, локальные проверки; запись только для разрешённых изменений, коммита и тега. Сеть, публикация и доступ к секретам не входят в обычную проверку. Не запрашивай расширение разрешений ради оценки сканера. Подробности: [INTEGRATION.md](references/INTEGRATION.md).

SKILL.md не обеспечивает автоматическую активацию. Для обязательного исполнения нужны проектные инструкции и независимые проверки Git/CI; событийный хук — дополнительный контроль. Для явно согласованного базового Git-профиля применяй [Completion Gate](references/ENFORCEMENT.md) и независимый Guarded Run; не считай protocol exit 0 или STRUCTURE_VERIFIED завершённым релизом. Не меняй внешнее окружение, baseline или marker.

## Политика микроверсий

1. Новый проект: 0.0.0. В существующем проекте определяй версию по его метаданным и Git; не переписывай выпущенные версии.
2. Каждое самостоятельное проверенное содержательное изменение увеличивает PATCH на 1.
3. .99 — рубеж, не предел. Если задача закончена и проверки пройдены, подготовь 0.0.99 → 0.1.0, 0.1.99 → 0.2.0 или 0.99.99 → 1.0.0.
4. Незавершённая задача на .99: продолжай .100, .101 и далее. После реального завершения и проверок возможен релиз, например 0.0.107 → 0.1.0.
5. Не создавай пустые изменения ради номера. VERSION, CHANGELOG и релизные документы входят в одну содержательную операцию.
6. Если сборка или обязательный тест не прошли, релиз не готов. Исправь причину и повтори проверки.
7. Это особая политика, а не стандартный SemVer. Не навязывай её проекту с несовместимыми правилами.

## Инструкция

1. Определи Git-root, HEAD, ветку, статус файлов, теги, версию, правила и разрешения.
2. Внеси конкретное изменение. Выполни обязательные сборки и тесты. Не выдавай непроверенное за завершённое.
3. Проверь HEAD и теги повторно. При нескольких агентах сериализуй операции релиза; при отсутствии надёжной координации блокируй фиксацию релиза. Не добавляй чужие файлы или весь рабочий каталог вслепую.
4. Рассчитай новую микроверсию, обнови метаданные, CHANGELOG и дорожную карту. Если предусмотрен перевод, обнови его вместе с оригиналом.
5. Создай содержательный коммит на русском, если политика проекта не требует иного. Теги рабочих микроверсий — по правилам проекта.
6. После завершения задачи на рубеже подготовь релиз MAJOR.MINOR.0 или MAJOR.0.0 и выполни реальные обязательные проверки.
7. Для каждого успешного релиза обязателен аннотированный тег Git, например v0.1.0 или microversion-release/v0.1.0. Аннотация описывает реальный результат. Проверь тип tag, непустую аннотацию и точный релизный коммит.
8. Без корректного релизного тега статус BLOCKED / RELEASE_NOT_TAGGED. Если заявлена разрешённая публикация, проверь удалённый тег и идентичность коммита отдельно.
9. Локальный тег, удалённый тег, GitHub Release и артефакт — разные результаты. Перед отчётом перепроверь версии, Git, тесты, сборку, документы RU/EN и ограничения.

## Скрипты

Запускай из каталога установленного навыка.

| Скрипт | Действие | Граница |
| --- | --- | --- |
| scripts/next_version.py | work / release | Только расчёт |
| scripts/release_tag.py | verify / create | create создаёт локальный аннотированный тег после проверок и разрешения; без push |
| scripts/install.py | --platform, --apply | По умолчанию DRY-RUN, без перезаписи |

## Примеры

- Незавершённая задача: python scripts/next_version.py 0.0.99 --mode work → 0.0.100.
- Завершение после .107: python scripts/next_version.py 0.0.107 --mode release → 0.1.0. Расчёт не доказывает готовность.
- Проверка: python scripts/release_tag.py verify 0.1.0 --repo <project-root>.
- После успешных проверок и разрешения: python scripts/release_tag.py create 0.1.0 --repo <project-root> --message "Релиз 0.1.0 — исправлен запуск".
- Нет тега или неверный коммит: BLOCKED / RELEASE_NOT_TAGGED. Не заменяй ошибочный тег автоматически.

Подробности: [RELEASE_TAGS.md](references/RELEASE_TAGS.md), [STYLE.md](references/STYLE.md). Коммиты, CHANGELOG, аннотации и релизы описывают результат, а не формальные действия: «Исправлено восстановление после сбоя», не «chore: bump version».

## Устранение неполадок

Ошибка сборки/теста — исправь и перепроверь. Конфликт версии или HEAD — согласуй изменения. Занятый тег — проверь привязку, не перемещай. Нет полномочий или доказательств — BLOCKED либо NOT_VERIFIED. Отсутствие автоматической активации — проверь инструкции и независимое исполнение в конкретном агенте.

## Финальный отчёт

Укажи COMPLETE, PARTIAL, BLOCKED или NOT_VERIFIED; версии до/после, реальные изменения, тесты и сборку, SHA коммита и объекта аннотированного тега, локальную и удалённую публикацию, наличие GitHub Release/артефакта и ограничения. Без подтверждённого тега релиз не завершён. Не обещай фоновой работы.
