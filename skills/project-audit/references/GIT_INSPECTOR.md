# Git Inspector — инструмент уровня II

[**Русский — оригинал**](GIT_INSPECTOR.md) | [English — перевод](GIT_INSPECTOR.en.md)

`python scripts/git_inspector.py --root <project-root>` получает HEAD (включая unborn/detached), счётчики изменённых, конфликтных и неотслеживаемых путей, локальных веток, аннотированных и прочих тегов, число remote. GitHub и сеть не требуются. Имена путей, веток и адреса remote не выводятся. Две последовательные сверки status/refs/remote names обнаруживают часть изменений: OBSERVED — одинаковые наблюдения, STALE — различие (код 1); ошибка Git/входа — код 2. SHA-256 status и refs — отпечатки наблюдаемых данных, а не содержимого или атомарного снимка. Счётчик аннотированных тегов не доказывает корректность релизов.

Использовать только доверенный стабильный checkout, установленный Git и разрешённую команду. Git status может читать содержимое и выполнять локально настроенные фильтры; инструмент не песочница. Дочерний Git получает только явный список системных переменных; произвольные переменные приложения и унаследованные GIT_* исключены, optional locks, fsmonitor и глобальная/системная конфигурация отключены, lazy fetch запрещён в поддерживающем Git. Не запускает сетевые команды. Не учитывает рабочие деревья submodules, игнорируемые файлы, содержимое, remote refs и подмены, исчезнувшие между наблюдениями. 15 секунд на команду, 4 MiB после захвата, не жёсткая граница памяти или потомков. Не использовать как доказательство безопасности или чистоты всего проекта. Исторически локальные Linux тесты 13/13. На кандидате 45eaeed021eb4fc36c805d2260aa2d0071f1abdd Windows CI 45627814264 прошёл все 14 тестов Git Inspector; весь Project Audit — 43 PASS и 1 FIFO SKIP. Инструмент принят в v0.0.76 после полного CI PR #74; агентная приёмка NOT_VERIFIED.

Кандидат защиты контекста нативных фикстур: setup изменяющих Git unit tests отклоняет наследуемые имена Git_* кроме GIT_PAGER до создания временного каталога или запуска Git. Production-политика и полномочия не изменяются. Не очищать окружение ради PASS. Позитивные реальные Git-тесты выполнять из обычного доверенного терминала с естественно допустимым контекстом; FIXTURE_GIT_CONTEXT_UNSAFE означает BLOCKED, не клиентскую приёмку. Синтетическая Linux-проба двух временных репозиториев подтвердила, что Git -C не предотвращает перенаправление локальной записи config через GIT_DIR; неполная индексированная пара вызвала exit 128. Это доказательство риска фикстуры, не причина каждого ERROR из отчёта владельца. Новый regression test требует CI.
