# Evidence Core — локальный инструмент уровня II

[**Русский — оригинал**](EVIDENCE_CORE.md) | [English — перевод](EVIDENCE_CORE.en.md)

`python scripts/evidence_core.py --register <register.json>` валидирует явно предоставленный JSON, не читает проект, не исполняет проверки и не обращается к сети. Формат v1: `schema_version: 1`, `snapshot: {id, fingerprint, as_of}`, `evidence: [{id, snapshot_id, fingerprint, scope, kind, result, source, observed_at, limitations}]`, `criteria: [{id, scope, evidence_ids}]`. Идентификаторы и scope — неприватные метки, fingerprint — 64 строчных hex-символа или null. Используй единый явно определённый способ получения отпечатка для всех записей одного снимка; SHA коммита или метаданных сам по себе не доказывает содержимое, окружение или чистоту. Дата UTC в формате YYYY-MM-DDTHH:MM:SSZ; as_of заявляет время снимка, не является доверенным временем. Не помещай секреты и частные пути в реестр.

Виды: CHECK, OBSERVATION, OWNER_REPORT, INFERENCE. Результат: PASS, FAIL, NOT_RUN, UNKNOWN. Для каждого критерия связываются существующие ID доказательств, проверяется точное совпадение scope, ID снимка и ненулевого отпечатка. Несовпадение снимка/отпечатка — stale; отсутствующий отпечаток — unbound; остальные виды — indirect, не заменяют CHECK. PASS и FAIL одного критерия сохраняются как CONFLICTING; отдельные FAIL_RECORDED и PASS_RECORDED означают только записи в реестре. Если подходящих записей нет, но есть stale — STALE, иначе NOT_VERIFIED. Даже PASS_RECORDED не устанавливает COMPLETE и не удостоверяет источник. При нескольких требуемых проверках разделяй критерии на отдельные точные scope; не считай любой PASS достаточным для всех условий. Отчёт включает все категории и счётчики, но не source/limitations; сохраняй исходный реестр приватно. Отпечаток канонического JSON относится к реестру, не к проекту, и чувствителен к порядку массивов.

Код выхода 0 означает валидную структуру, включая зарегистрированные FAIL/CONFLICTING; 2 — ошибка входа. До 2 MiB входа, 2000 записей и критериев каждого вида, до 100 ссылок на критерий. Дубликаты ID и ключей JSON, неизвестные ссылки, некорректные даты и наблюдения позже as_of отвергаются. Не проверяет подлинность, полноту, текущее состояние файлов, фактическое время, семантику scope и выполнение. Это не валидатор релиза и не песочница. 15/15 Linux и 15/15 Windows 11 / Python 3.14.3; принятый v0.0.78, main CI 45658775191 SUCCESS, независимый тег project-audit/v0.0.4 подтверждён.
