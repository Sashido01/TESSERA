# Инвентаризация — эксперимент уровня II

[**Русский — оригинал**](INVENTORY.md) | [English — перевод](INVENTORY.en.md)

`python scripts/inventory.py --root <project-root>` — отдельный кандидат инструмента Project Audit. Запускай только из доверенного установленного навыка над явно выбранным стабильным снимком. Не изменяет проект и не исполняет его код. На stdout — JSON с относительными путями, размерами, временем изменения, расширениями, маркерами технологического стека и границами обследования. Имена файлов сами могут содержать конфиденциальные данные; не отправляй JSON внешним сервисам без разрешения.

По умолчанию максимум 10 000 объектов и глубина 32 (допустимый максимум 50 000 и 64). Исключённые каталоги перечислены в `excluded_names`, фактически встреченные — в `gaps`. `SCOPED_COMPLETE` означает только обход заявленной области метаданных, а не полный аудит. Любая обнаруженная нештатная граница означает `PARTIAL`, код выхода 1. Ошибка входа/доступа к корню — код 2. Не следуем известным ссылкам и reparse points; не переходим на другое устройство. На Linux проверено на временных деревьях; Windows junction проверен только синтетической проверкой флага, реальное поведение junction — NOT_VERIFIED; это отдельное ограничение от нативной проверки исправления #80.

`metadata_sha256` хеширует отсортированные записи путей, размеров, mtime, каталогов, исключений и лимитов. Это НЕ хеш содержимого: изменение байтов при сохранении длины и mtime не обнаруживается (отрицательный контроль есть в тестах). `content_integrity=NOT_VERIFIED` всегда. Это не доказательство неизменности проекта или безопасности исполнения. Нет атомарного снимка; гонки подмены пути, mount/bind mount на том же устройстве, изменение содержимого без смены метаданных, сетевые FS и объём JSON не полностью контролируются. Используй стабильный доверенный снимок, не рассматривай инструмент как песочницу. При необходимости точное хеширование разрешённых файлов — отдельная следующая задача.

Проверка владельца 25.11.2026 на Windows Python 3.14 (каталог v0.0.74, Project Audit 0.0.2) выявила ложный DEVICE_BOUNDARY для вложенных каталогов: `DirEntry.stat()` на Windows обнуляет `st_dev`/`st_ino` по документированному контракту Python. Кандидат #80 использует свежий `os.stat(path, follow_symlinks=False)` для каждого обычного каталога, проверяет тип, перенаправление и устройство, сохраняет сверку идентичности до обхода. Linux Python 3.13.5: моделирование нулевых полей RED на исходнике, GREEN после исправления, Inventory Engine 21/21 (17+4), включая защиту от другого устройства, перенаправления, отказа stat и замены каталогом-файлом. Исправление принято в v0.0.76 после нативного Windows CI PR #74; реальные junction/mount race и TOCTOU не устранены. [Документация Python](https://docs.python.org/3.14/library/os.html#os.DirEntry.stat), [Issue #80](https://github.com/Sashido01/TESSERA/issues/80).
