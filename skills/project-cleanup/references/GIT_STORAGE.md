# Git и GitHub: независимые области хранения

[**Русский — оригинал**](GIT_STORAGE.md) | [English — перевод](GIT_STORAGE.en.md)

Только в доверенном выбранном Git-контексте. Если контекст небезопасен, не очищать переменные для продолжения, а вернуть BLOCKED. Сначала `git status --porcelain=v2`, `git worktree list --porcelain`, `git count-objects -vH`, `git ls-files -z`; ignored/untracked через отдельную `git ls-files --others --ignored --exclude-standard -z` и `git ls-files --others --exclude-standard -z`. Это отдельные метрики: рабочее дерево, index, общая object database, refs и remote. Не складывать их как физический объём. Сохраняй сырые пути локально.

Для Git-истории опционально официальный [git-sizer](https://github.com/github/git-sizer) (проверить версию и происхождение до установки): крупные достижимые blobs, глубина дерева, число объектов, refs. [git count-objects](https://git-scm.com/docs/git-count-objects) — локальные loose/pack counters, не серверный объём. [git clean](https://git-scm.com/docs/git-clean) имеет preview, но игнорирование не означает безопасность; не использовать массовый destructive clean. [git maintenance](https://git-scm.com/docs/git-maintenance) и [git gc](https://git-scm.com/docs/git-gc) могут трогать общую базу объектов, reflog и worktrees; не запускать автоматически. Не делать агрессивный prune, GC или переписывание истории ради экономии. Удаление файла новым коммитом не удаляет предыдущие blobs.

GitHub: отдельно инвентаризировать размер репозитория по metadata (приближение), текущие tracked blobs, Actions artifacts (размер/expiry/назначение/ссылка на релиз и доказательства), Actions caches (ключ/ветка/доступ/размер), Releases assets, LFS, Packages при наличии и полномочиях. Не подменять отсутствие прав нулём. Пагинация обязательна для полного отчёта. Не считать сумму артефактов размером Git. [Удаление artifacts](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/remove-workflow-artifacts) необратимо; сначала подтвердить сохранность доказательств, аттестаций, релизных файлов и возможность воспроизведения. Исторические failed runs не являются мусором автоматически. Кеши ускоряют CI; сравнить стоимость повторного скачивания/сборки. Сроки и лимиты согласовать по проекту и возможностям аккаунта; см. [настройки хранения](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository), [dependency caching](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching). Удаление по точному ID только с правами и после повторной сверки. Приватные paths, tokens и raw reports не публиковать.

Профилактика: не коммитить регенерируемые данные, настроить точечный .gitignore и хранение сборок/кешей вне исходников в выделенной области; проверять размер изменений, не вводить автоматический лимит, который ломает нужные файлы или release evidence. При отсутствии GitHub локальная работа остаётся полноценной.
