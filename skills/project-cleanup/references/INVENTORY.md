# Инвентаризация

[**Русский — оригинал**](INVENTORY.md) | [English — перевод](INVENTORY.en.md)

Помощник `python -B scripts/inventory.py --root <project-root>` работает с явно выбранным обычным каталогом. Не выбирай корень диска или профиль пользователя. Обход метаданных: не открывает содержимое файлов, не выполняет Git, не пишет на диск и не использует сеть. Ссылки, reparse points, объекты другого st_dev, .git, вложенные рабочие Git-репозитории, специальные файлы пропускаются. На доверенной стабильной ФС; одинаковый st_dev не исключает bind mount, подмены родителей и гонки не гарантированно предотвращены. Не считать обход песочницей.

По умолчанию до 200000 объектов, 64 уровней и 30 секунд между операциями (не прерывает зависший системный вызов). Настраиваемые пределы, выход 0 OBSERVED, 1 PARTIAL при ошибке/превышении бюджета, 2 BLOCKED при недопустимом корне или аргументах. OBSERVED относится только к определённой области с явными исключениями, не к целому диску, атомарному снимку или полной Git-инвентаризации. При PARTIAL не экстраполируй объём.

`logical_bytes` — сумма st_size по именам обычных файлов. Hardlink aliases учитываются в логической сумме отдельно; счётчик наблюдаемых алиасов не означает физическую экономию. Разреженные файлы, сжатие, reflinks, дедупликация, ACL и внешние ссылки не позволяют вычислять освобождение места по st_size. Измерять свободное место до/после на том же томе и при сопоставимой нагрузке; фоновые процессы могут влиять на разность. Не объявлять весь delta следствием очистки без контроля.

Категории review_cache, review_build, review_dependency, review_temp — подсказки, не разрешения. protected_hint включает data, backups, evidence, models, logs, секретоподобные имена и расширения; other остаётся UNKNOWN. Даже совпадение с ignore не доказывает воспроизводимость. Для реального плана проверить tracked/ignored/untracked, lockfiles, текущие сборки, потребителей, права и разрешения.

`--details` добавляет до 20 относительных путей крупных REVIEW-файлов (по умолчанию их нет). Это приватные метаданные; не переносить в публичные логи, Issues или Git. Сравнить агрегаты до/после при одинаковых лимитах и исключениях; зафиксировать число пропусков. Пустая выдача не доказывает отсутствие мусора. Отдельно измеряй длительность сканирования и rebuild cost: не удаляй полезный кеш только ради меньшего числа.

Дополнительные пределы: 8192 ожидающих каталогов и 100000 уникальных hardlink identities; превышение даёт PARTIAL. Явный .. в корне отклоняется. Согласно [Python os.DirEntry.stat](https://docs.python.org/3.14/library/os.html#os.DirEntry.stat), Windows возвращает нули для st_dev/st_ino/st_nlink; для обычного объекта используется отдельный os.stat(follow_symlinks=False), не для распознанного reparse point. Это дополнительная стоимость метаданных ради корректности; реальный Windows runtime требуется.

Приватные детали также показывают до 20 крупнейших групп каталогов первого уровня (null — файлы в корне). Агрегация хранит до 8192 групп; private_top_level_complete=false обозначает пропуск групп, не изменение общих метрик. Группа не является разрешённой целью удаления.

Усиление границ: известные каталоги учётных данных не перечисляются; их объём неизвестен, исключения отражает sensitive_dirs. Явный корень в таком каталоге или Git metadata, домашний профиль и его предки отклоняются. Если профиль не определён — BLOCKED, не изменять окружение хоста. Защитные признаки расширены именами и основами имён учётных данных, ключей и токенов. Регрессии контролируют отсутствие открытия содержимого; это не песочница и не исчерпывающий детектор чувствительных имён.

BLOCKED содержит фиксированный машинный reason (например ROOT_PROFILE_UNKNOWN или LIMIT_INVALID); ошибки ОС не выводятся с путями. Не исправляй отсутствие разрешения изменением sandbox; используй отдельно разрешённый доверенный процесс.
