# История изменений TESSERA

[**Русский — оригинал**](CHANGELOG.md) | [English — перевод](CHANGELOG.en.md)

Здесь фиксируются изменения **общего каталога**. Истории отдельных навыков могут вестись в их собственных папках.

## 0.0.20 — Безопасная установка Agent Skill официальным GitHub CLI (T10.01)

- Добавлен действительный CI-сценарий `gh skill install --from-local --dir` и `gh skill list --dir` для `microversion-release`, строго во временном каталоге, без доступа к пользовательскому профилю.
- Повторно используется официальный, проверенный по SHA-256 бинарный `gh 2.105.0`. Новый `tools/check_official_local_install.py` проверяет сохранность исходников, Markdown-тела навыка, зависимых файлов и инъекцию source metadata.
- Проверяется запрет совмещения `--from-local` с `--pin`, отсутствие реальной публикации и превентивный отказ при уже занятом каталоге назначения. Добавлены негативные тесты.
- Аудит официального исходного кода обнаружил риск перезаписи в `InstallLocal` без `--force`: прямую повторную локальную установку в пользовательский профиль запрещено считать безопасной. Собственный офлайн-установщик сохраняет отказ при существующей папке.
- Обновлены двуязычные документы, политика и дорожная карта. Реальная **удалённая** установка `--pin` по тегу/SHA и проверка агентских клиентов остаются NOT_VERIFIED.

**Приёмка:** T10.01 COMPLETE только после фактического успешного CI на настоящем `gh`. T10 целиком PARTIAL, T09.10 отдельно OPEN.

## 0.0.19 — Реальная изолированная проверка gh skill publish --dry-run

- Подготовлен запуск официального `gh skill publish --dry-run` в CI на изолированной временной копии всех навыков, без GitHub remote и токенов. Используется строго `gh 2.105.0` из официального GitHub Release по независимо проверенному SHA-256 скачанного архива.
- `tools/run_publish_dry_run.py` проверяет CLI, положительный и отрицательный сценарии, отсутствие удалённого репозитория и сохранность файлов по SHA-256 дерева навыков; при ошибке отказывает без вывода секретов и приватных путей.
- Добавлены негативные тесты, двуязычная инструкция, согласованы ROADMAP, README, AGENTS.
- Реальная проверка GitHub topics, GitHub Release и авторизованного remote **не выполняется**; T09.10 и клиентская интеграция остаются отдельными этапами.

**Приёмка:** локальная публикационная проверка T11.02 требует фактического SUCCESS в CI; никакое неподписанное ZIP или mock CLI не служат доказательством успешной публикации.

## 0.0.18 — Обновлены GitHub Actions до Node.js 24

- Обновлены закреплённые SHA официальных `actions/checkout` v7.0.1, `actions/setup-python` v7.1.0 и `actions/upload-artifact` v7.0.2 в обычном CI и подписывающем workflow. Для `actions/attest` подтверждено, что текущий закреплённый SHA соответствует v4.2.2 на Node.js 24, поэтому менять его без причины не потребовалось.
- Добавлен `tools/check_actions_runtime.py`: проверка точных SHA, количества и набора Actions в обоих workflow; CI запускает её как обязательный шаг. Добавлены отрицательные тесты на откат, незакреплённые версии и чужой Action.
- Сохранены защита `main`, аннотированные теги, отдельный signing workflow, наименьшие права, отключение сохранённых credentials и проверка ancestry.
- Двуязычная документация и дорожная карта обновлены. Исполнение подписывающего workflow и действительная GitHub attestation по-прежнему NOT_VERIFIED.

**Приёмка:** T08.01 считается COMPLETE только при успешном CI Pull Request и `main` с опубликованным аннотированным тегом, а также отсутствии прежнего Node.js 20 warning в журнале обновлённых Actions. T08 в целом остаётся PARTIAL.

## 0.0.17 — Эталонная проверка формата Agent Skills в CI

- Подключён эталонный `skills-ref validate` из официального `agentskills/agentskills`, закреплённого по точному SHA `83021e2be457a9b6679148719c1f6074f0ad975e`. Дополнительный checkout выполняется после собственных тестов и упаковки каталога.
- Зависимости `skills-ref` зафиксированы версиями и хешами wheel; проверка не устанавливает непроверенный одноимённый пакет из PyPI.
- Добавлен безопасный wrapper для всех навыков с отказами при проблемах CLI, имен, symlink, таймаутах и некорректном результате; добавлены модульные тесты.
- Подготовлено двуязычное руководство [AGENT_SKILLS_STANDARD](docs/AGENT_SKILLS_STANDARD.md), обновлены правила проекта и ROADMAP.

**Ограничения:** reference implementation обозначена её авторами как демонстрационная, не production. Реальное `gh skill publish --dry-run` ещё не проверено; интеграция навыков с клиентами NOT_VERIFIED. T11 PARTIAL, до успешного CI T11.01 NOT_VERIFIED.

## 0.0.16 — Защита проверки attestation от уязвимых версий GitHub CLI

- Перед `gh attestation verify` введена обязательная проверка версии установленного `gh`. Минимум `2.102.0` — версия с исправлениями GHSA-wjmr-j3rp-mh2g и GHSA-4mq3-hpgx-9cx8 от 30.09.2026.
- Неизвестная, старая, некорректная или не полученная из CLI версия приводит к `BLOCKED`, а не к ложному `PASS`. Проверка ограничена таймаутом; stderr и приватные пути не копируются в отчёты.
- Добавлены положительные и отрицательные тесты, актуализированы русский и английский оригиналы документации по происхождению, доверенной сборке и дорожной карте.
- Реальный запуск signing workflow и проверенная публикация не заявляются: T09.10 — PARTIAL, attestation — NOT_VERIFIED.

## 0.0.15 — Проверка фактических байтов ZIP без распаковки

- Добавлен `tools/verify_catalog_package.py`: офлайн-проверка структуры ZIP, обязательных файлов, манифеста, SHA-256 каждого файла, версии и внешнего полного SHA исходного коммита.
- Архив отклоняется при опасных путях, symlink, повторениях, недопустимом формате, превышении лимитов и подмене байтов; содержимое ZIP не исполняется и не извлекается.
- Добавлены отрицательные тесты и двуязычное руководство [CATALOG_VERIFICATION](docs/CATALOG_VERIFICATION.md).
- Разделены проверка внутренней целостности и независимая криптографическая аттестация: статус подписи и публикации остаётся NOT_VERIFIED.

**Ограничения:** реальная подпись пакета, публикация и проверка в целевых клиентах остаются NOT_VERIFIED; T09 PARTIAL. CI для этой микроверсии требует отдельной проверки после PR.

## 0.0.14 — Детерминированный пакет каталога и подготовка доверенной attestation

- Реализован `tools/build_catalog_package.py`: реальный исходный ZIP Agent Skills с фиксированными ZIP-метаданными, LICENSE, VERSION, runtime-файлами навыков, манифестом по SHA-256 и полным Git-коммитом.
- Добавлен отдельный `build-attested-catalog.yml` с **ручным запуском по аннотированному тегу**, правами только на чтение исходников и создание GitHub/Sigstore attestation. Все внешние Actions закреплены полными SHA; GitHub Release автоматически не создаётся.
- `release-checks.json` теперь содержит настоящую обязательную сборку каталога вместо пометки NOT_APPLICABLE. Обычный PR CI собирает пакет и проверяет воспроизводимость без OIDC или signing.
- Добавлены проверки безопасности signing workflow и отрицательные сценарии недоверенного ref, неправильного тега, произвольных файлов и изменений исходников.
- Упрощён Git-процесс: **одна ветка на логически связанную цель и один PR**, а не новая ветка на каждое техническое исправление. Закреплено в [BRANCHING](docs/BRANCHING.md) на двух языках.
- Обновлены русские оригиналы и английские переводы roadmap, VERSIONING, GITHUB_SECURITY, архитектуры, README и AGENTS.

**Ограничения:** запуск workflow по реальному тегу и фактическое создание/проверка attestation пока NOT_VERIFIED. Новый пакет сохраняется в GitHub Actions Artifacts, а не в GitHub Releases; подписывающий workflow не подписывает исполняемые приложения. T09 остаётся PARTIAL.

## 0.0.13 — Проверка подписанного происхождения релизного артефакта

- Добавлен `core/release_provenance.py`: независимая проверка локального файла относительно GitHub Release metadata и криптографической Sigstore/SLSA attestation через официальный `gh attestation verify`.
- Аттестация ограничена точным репозиторием, SHA исходного коммита, Git-тегом, конкретным подписывающим workflow и предикатом SLSA provenance v1; самоподписанный результат от произвольного workflow не принимается.
- Добавлены безопасные отказы при подмене байтов/файла, неподтверждённой публикации, недоступном CLI, неуспешной подписи, неправильном JSON и изменении файла при проверке.
- `core/release_report.py` расширен `--verify-provenance --artifact-file --signer-workflow`; проверка отключена по умолчанию и не сохраняет локальные пути в отчётах.
- `core/release_certificate.py` различает подписанную GitHub attestation и **неподписанное итоговое свидетельство TESSERA**; готовность приложения всегда NOT_VERIFIED.
- Добавлены 33 тестовых сценария, русский оригинал `docs/RELEASE_PROVENANCE.md` и полный английский перевод, обновлены архитектура, roadmap, README, AGENTS и техническая документация.

**Границы:** у каталога TESSERA нет опубликованного и подписанного реального артефакта. Тесты используют управляемый ответ официального CLI, не доказывая успешную аттестацию работающего выпуска. Доверенный build workflow, настоящая публикация и конкурентное управление релизами остаются открытыми. T09 — PARTIAL.

## 0.0.12 — Потоковая проверка настоящих байтов release assets

- Добавлен независимый `core/release_assets.py`: проверка размера и SHA-256 скачанных байтов прикреплённых GitHub Release assets относительно метаданных официального API.
- Введены ограничение памяти потоковым чтением, максимальные размеры файлов, блокировка недоверенных URL и перенаправлений, строгая проверка нужного репозитория/тега/файла.
- Расширен `core/release_report.py`: сетевой режим `--verify-assets` допускается только с явным `--verify-publication`, результата байтовых проверок нет по умолчанию.
- В свидетельстве `core/release_certificate.py` сохранено различие между подтверждением содержимого файла, происхождением сборки и готовностью приложения; SHA-256 самого свидетельства остаётся неподписанным.
- Добавлены 32 тестовых сценария, в том числе отрицательные проверки повреждённых байтов, усечения, размера, чужих URL, отсутствующих digest и публикации.
- Подготовлены оригинал `docs/RELEASE_ASSETS.md` на русском языке и полный английский перевод; обновлены roadmap, архитектура, README, AGENTS, отчёты и история изменений.

**Ограничения:** реальных опубликованных GitHub Releases у TESSERA на момент проверки нет. Поэтому сквозная сетевая проверка реального опубликованного файла NOT_VERIFIED. Происхождение сборки, цифровая подпись и готовность исполняемого ПО также NOT_VERIFIED; T09 остаётся PARTIAL.

## 0.0.11 — Проверка фактической публикации GitHub Release и доказательное свидетельство

- Добавлен `core/release_publication.py`: только чтение metadata опубликованного GitHub Release с проверкой точного тега, draft/prerelease, даты, GitHub URL и состояния файловых assets.
- Введена привязка именованного доверенного Git remote к `github.com/owner/repository`: чужой URL, локальный bare Git и хост-подделка не считаются GitHub-публикацией.
- Добавлен `core/release_certificate.py`: структурированное неподписанное свидетельство с воспроизводимым SHA-256 собственных полей, отдельными состояниями публикации исходников и готовности приложения.
- Расширен `core/release_report.py`: `--verify-publication` и `--format certificate`, публикация без явного запроса не проверяется и не производится.
- Добавлены 39 положительных и отрицательных сценариев проверки metadata, чужого remote, отсутствия доказательств, неподписанного хэша и интеграции с отчётом.
- Обновлены дорожная карта, архитектура, README, AGENTS и двуязычная документация T09.01–T09.05.

**Ограничения:** на момент проверки у TESSERA не было GitHub Releases. Новая версия не создаёт Release. Проверка реальной публикации на живом выпуске пока NOT_VERIFIED; байты assets, подписи и готовность исполняемого приложения не проверяются. Весь T09 остаётся PARTIAL.

## 0.0.10 — Независимая проверка завершённого GitHub Actions и состояния доказательств

- Добавлен `core/release_ci.py`: проверка завершённого GitHub Actions run по официальному REST API с точным SHA коммита, ожидаемым workflow, событием push в main и обеими обязательными jobs.
- При несовпадении номера попытки, отсутствии, пропуске или ошибке обязательной job, неполной выдаче API и сетевых проблемах возвращается BLOCKED, а не ложный PASS.
- Добавлен независимый `core/release_state.py`, который определяет уровни доказательств, не создавая фиктивного статуса RELEASED.
- `core/release_report.py` расширен явным `--verify-ci`, выбором доверенного GitHub-репозитория и идентификатора завершённого run, а также полями CI в JSON/Markdown.
- Добавлены 32 сценария, включая положительные и отрицательные ответы GitHub API, неполную пагинацию, несовпадающие SHA/attempt и отсутствие сетевого доступа в режиме по умолчанию.
- Русская документация обновлена как оригинал, английская — полным переводом; исправлено устаревшее описание защиты main.

**Ограничение:** публичные workflow проверяются без обязательного токена только по явному запросу. Внутри того же незавершённого workflow проверка статуса completed не выполняется. Результат T09.04 не доказывает реальную публикацию приложения; весь T09 по-прежнему PARTIAL.

## 0.0.9 — Проверка удалённого аннотированного тега и итоговый отчёт по фактам

- Добавлен `core/release_remote.py`: проверка точного удалённого `refs/tags/<version>` и SHA **объекта аннотированного тега**, с отказом при отсутствии тега, несовпадении или сетевой ошибке.
- Добавлен `core/release_report.py`: структурированные JSON и Markdown-отчёты, объединяющие локальный Git, Release Preflight и явно запрошенные remote-доказательства.
- По умолчанию отчёт ничего не публикует, не выполняет команды сборки/тестов и не обращается в сеть. Доступ к remote и выполнение команд разрешаются отдельными явными флагами.
- Добавлены 20 модульных тестов на временных локальных Git-репозиториях, включая несоответствие объекта тега при одинаковом commit SHA, исторический выпуск и неполные доказательства.
- В job автоматического тегирования добавлена независимая проверка после создания аннотированного тега, с реальным запросом к Git remote.
- Согласованы русский оригинал и английский перевод ROADMAP, README, AGENTS и специализированной документации.

**Ограничение:** `evidence_status=PASS` подтверждает только запрошенные проверки, а `release_readiness` остаётся `NOT_VERIFIED`. Контроль внешних CI/пакетов, полнота тестового покрытия, механизм `RELEASED` и конкурентные релизы ещё не реализованы. T09 остаётся PARTIAL.

## 0.0.8 — Добавлены предварительная проверка релиза и выполнение обязательных тестов по разрешению

- Реализован `core/release_preflight.py`: проверка версии и CHANGELOG в точном Git-коммите, чистоты рабочей копии, корректности объявленных build/test шагов.
- Введены два режима: безопасный `--plan` (по умолчанию, без запуска команд) и явный `--execute` с исполнением только утверждённого файла конфигурации и `shell=False`.
- Добавлен `release-checks.json` для TESSERA; отсутствие собственного сборочного артефакта указано как NOT_APPLICABLE с объяснением, две группы тестов обязательны.
- Добавлены 22 сценария на отказ при неверной версии, неполных релизных заметках, грязной рабочей копии, невалидной конфигурации, ошибках выполнения и таймаутах.
- CI проверяет `--plan`, не исполняя из PR произвольные команды; проверки `--execute` проводятся в изолированных временных Git-репозиториях.
- Подготовлены русские оригиналы и английские переводы документации, обновлена дорожная карта.

**Границы:** PASS при выполнении команд означает лишь успешные локальные шаги; инструмент не проверяет внешние CI, подписи, удалённые теги и GitHub Release. T09 остаётся PARTIAL, `release_readiness=NOT_VERIFIED`. T08 остаётся PARTIAL из-за непроведённых рискованных отрицательных испытаний.

## 0.0.7 — Начата независимая проверка доказательств релиза

- Добавлен независимый `core/release_inspect.py`: только чтение Git-истории, `VERSION` конкретного коммита и аннотированного тега.
- Реализована проверка **исторического** релиза по полному SHA без ошибочной привязки только к текущему HEAD.
- Предусмотрены явные ошибки для отсутствующего, легковесного, неправильно привязанного тега и несовпадения версии.
- Добавлены 13 модульных сценариев, включая проверки без побочных Git-операций.
- Зафиксированы результаты полного цикла приёмки T08: отрицательный PR — FAIL, исправленный PR — PASS, squash merge, подтверждённый аннотированный `v0.0.6`.
- Обновлены русские и английские документы, дорожная карта и границы проверки.

**Ограничения:** инспектор не выполняет сборку/тесты и не проверяет remote. Его PASS — доказательство корректности Git-тега и VERSION, но не готовности релиза. T09 — PARTIAL; T08 — PARTIAL с оставшимися непроверенными административными и теговыми сценариями.

## 0.0.6 — Проверена блокировка некорректного изменения через Pull Request

- Через GitHub API подтверждены два активных Rulesets: защита основной ветки и ранее опубликованных тегов.
- Создан Pull Request #1 с намеренно неправильной версией `0.0.99` вместо `0.0.6`; проверка `validate` отказала из-за нарушенной последовательности и отсутствующих записей CHANGELOG.
- Подтверждено, что после FAIL задача тегирования не запускалась и ошибка блокирует Pull Request.
- Исправленная версия `0.0.6` и двуязычные документы подготовлены для повторной проверки и слияния через squash.

**Открытая проверка:** успешное слияние исправленного Pull Request и выпуск аннотированного `v0.0.6`; до подтверждения T08 остаётся PARTIAL.
