# Как участвовать в TESSERA

[**Русский — оригинал**](CONTRIBUTING.md) | [English — перевод](CONTRIBUTING.en.md)

Спасибо за предложения и исправления. Главная цель — небольшие, понятные и проверяемые изменения.

## Перед изменением

- Проверь существующие навыки и задачи, чтобы не дублировать работу.
- Для нового навыка создай `skills/<slug>/SKILL.md` и `README.md`. Имя `slug` — строчные латинские буквы, цифры и дефисы.
- В `SKILL.md` укажи корректные YAML-метаданные `name` и `description`. Описание объясняет, в какой ситуации навык полезен.
- Инструкции должны быть точными, без фиктивных возможностей и неявных опасных действий.
- Скрипты, если они есть, должны иметь понятный способ запуска и тесты. Не добавляй секреты и машинно-зависимые пути как обязательные настройки.
- **Сначала напиши документацию на русском языке**, затем добавь полный перевод `*.en.md` в том же изменении. Для навыка переводи `SKILL.md` в `references/SKILL.en.md`, не создавая вторую точку входа. См. [языковую политику](docs/I18N.md).

## Проверка

```bash
python tools/validate_skills.py
python tools/check_public_paths.py
python tools/check_translations.py
python -m unittest discover -s tests -v
python -m unittest discover -s skills/microversion-release/tests -v
```

Если среда недоступна, явно перечисли непроведённые проверки.

## Коммиты и Pull Requests

- Используй простой русский язык: «Исправлен расчёт следующей версии при переходе через 99», а не «misc fixes» или «bump».
- Описывай в Pull Request цель, изменения, проверки, ограничения и возможные риски совместимости.
- Один Pull Request желательно посвящать одной связанной задаче.
- Не переписывай опубликованные теги и чужую историю.
- Для безопасности открывай непубличное сообщение об уязвимости, если функция доступна; не раскрывай секреты в Issues.

## Лицензирование

Отправляя изменения, учитывай, что проект распространяется под лицензией MIT.
