# TESSERA

[**Русский — оригинал**](README.md) | [English — перевод](README.en.md)

**Единая библиотека навыков для AI-агентов.** Каждый навык — самостоятельный модуль, который можно использовать, проверять и развивать независимо от остальных.

TESSERA не является форком Harness или Codex. Здесь хранятся переносимые инструкции [Agent Skills](https://agentskills.io/), скрипты и примеры их подключения. Поддержка конкретной агентной среды и автоматический запуск проверяются отдельно.

## Как устроен репозиторий

```text
skills/                 Независимые навыки с SKILL.md
tools/                  Общие проверки каталога
docs/                   Правила, архитектура и дорожная карта
.github/workflows/      Автоматическая проверка при изменениях
```

## Начало работы

1. Откройте папку нужного навыка в `skills/` и прочитайте его `README.md`.
2. Установите **всю папку навыка** в каталог навыков своей агентной системы, а не один `SKILL.md`.
3. Проверьте, что система обнаруживает навык. Автоматическое применение зависит от конфигурации конкретного агента.
4. Прежде чем разрешать агенту коммиты, теги или публикацию, проверьте правила репозитория и права доступа.

Для Microversion Release: [инструкция установки](skills/microversion-release/README.md).

## Проверка

Нужен Python 3, сторонние библиотеки не требуются.

```bash
python tools/validate_skills.py
python tools/check_public_paths.py
python tools/check_translations.py
python tools/check_repository_version.py
python -m unittest discover -s tests -v
python tools/run_skill_tests.py
```

Скрипт вычисления следующей версии ничего не записывает:

```bash
python skills/microversion-release/scripts/next_version.py 0.0.99 --mode work
python skills/microversion-release/scripts/next_version.py 0.0.100 --mode release
```

Результаты: `0.0.100` и `0.1.0` соответственно. **Второй пример — только расчёт номера:** он не удостоверяет завершение задачи или сборку.

## Независимая проверка ZIP каталога

[Инструмент T09.09](docs/CATALOG_VERIFICATION.md) проверяет скачанный пакет без распаковки: состав, MANIFEST.json, фактические SHA-256 и соответствие внешнему SHA коммита. Это **не** проверка подписи GitHub и не доказательство публикации. Реальная аттестация и сквозная проверка ZIP v0.0.21 подтверждены в T09.10.

## Проверка безопасной локальной установки GitHub CLI

В CI испытывается реальный `gh skill install --from-local --dir` с последующим `gh skill list` на временной копии навыка. **Низкоуровневый InstallLocal не проверяет перезапись; штатный CLI проверяет существующий каталог.** Используйте новый пустой каталог и независимый guard. Удалённая установка по `--pin` проверена в T10.02. [Подробности](docs/GH_SKILL_INSTALL.md).

**T09.10 — COMPLETE:** реальный ZIP `v0.0.21` подписан и независимо проверен (SHA-256, манифест, Sigstore/SLSA). [Доказательства](docs/TRUSTED_BUILD.md). Приёмка относится только к этому файлу, не к последующим версиям. GitHub Release не создавался.

## Проверка без публикации через официальный GitHub CLI

CI также проверяет официальный `gh skill publish --dry-run` версии `2.105.0` из скачанного по SHA-256 выпуска в изолированной копии `skills/`, без GitHub remote и токенов. Тест проверяет успешную и ошибочную валидацию, не создавая GitHub Release. Это не проверка реального опубликованного выпуска. См. [GH_SKILL_PUBLISH_DRY_RUN](docs/GH_SKILL_PUBLISH_DRY_RUN.md).

## Проверка по стандарту Agent Skills

В CI дополнительно запускается [эталонный валидатор `skills-ref`](docs/AGENT_SKILLS_STANDARD.md) из зафиксированной ревизии официального репозитория и с зависимостями по SHA-256. Это проверка формата, не доказательство выполнения навыка агентом. Независимый `gh skill publish --dry-run` пока NOT_VERIFIED.

## Версионирование

**Текущая версия каталога:** файл [`VERSION`](VERSION). С этой точки каждое новое самостоятельное проверенное изменение TESSERA получает следующую микроверсию, запись в обоих CHANGELOG и Git-коммит с понятным русским сообщением. После успешной проверки GitHub Actions создаёт аннотированный тег `vX.Y.Z`; GitHub Release автоматически не публикуется.

- **Каталог TESSERA** и **каждый навык** имеют собственную историю изменений.
- Рабочие микроверсии увеличивают PATCH. После `.99` работу можно продолжить с `.100`, `.101` и далее, если задача не завершена.
- После завершения работы и успешных проверок плановый рубеж `0.0.99 → 0.1.0`, `0.1.99 → 0.2.0`, `0.99.99 → 1.0.0`.
- Не создавайте фиктивные коммиты или релизы ради красивого номера. Для новых проектов стартовая версия `0.0.0`; старые теги и историю не переписывают.
- При необходимости публиковать теги отдельных навыков используйте пространства имён, например `microversion-release/v0.1.0`, чтобы не конфликтовать с общими тегами каталога.

Подробности: [политика версий](docs/VERSIONING.md). Начальная историческая точка `0.0.0` сохранена; обязательная схема начинается с `0.0.1` без переписывания старых коммитов. GitHub Release и отдельные сборочные артефакты пока не опубликованы.

## Поддержка разных агентов

Первый навык построен на общем формате Agent Skills и может устанавливаться в **Codex, DeepSeek Harness, Claude Code, Hermes** и другие совместимые среды. Подготовлены [инструкции по интеграции](skills/microversion-release/references/INTEGRATION.md) и безопасный установщик с режимом предварительного просмотра. Для Hermes предусмотрено подключение TESSERA в качестве собственного каталога навыков (tap).

Выпуск версии приложения **не считается завершённым без проверенного аннотированного Git-тега**. Проверка: `python skills/microversion-release/scripts/release_tag.py verify 0.1.0 --repo <project-root>`. Скрипт не заменяет реальную сборку и тесты. Автоматическое применение навыка во всех агентах пока не подтверждено.

## План развития и ограничения

[Полная дорожная карта T00–T17](docs/ROADMAP.md) описывает проверяемые этапы защиты Git, создания единого Release Core, распространения навыков и интеграции с агентами. [Политика зависимостей](docs/DEPENDENCIES.md) закрепляет выбранный стек: официальный GitHub CLI как **планируемый основной способ распространения после реальных испытаний**, минимальный Python-установщик для офлайн-режима и нестандартных профилей.

NVIDIA SkillEvaluator допускается **только на Tier 1**, после проверки совместимости, затрат и работы без платных AI API. Tier 2 и Tier 3 не используются. Эталонный `skills-ref` планируется для проверки общего формата; собственные тесты TESSERA остаются обязательными для микроверсионности и тегов.

**Безопасность CI:** все внешние GitHub Actions закреплены по полным проверенным SHA и используют Node.js 24; точный состав и версии дополнительно проверяет `tools/check_actions_runtime.py`. См. [GITHUB_SECURITY](docs/GITHUB_SECURITY.md). Подписанный ZIP v0.0.21 независимо проверен.

## Защита GitHub

[Инструкция настройки Rulesets](docs/GITHUB_SECURITY.md) описывает проверяемые ограничения основной ветки и тегов. **Rulesets активны:** требуются Pull Request, `validate` и актуальная ветка; опубликованные теги защищены. Отрицательный тест CI прошёл ожидаемо. Отрицательный и положительный сценарии Pull Request, а также создание нового аннотированного тега подтверждены. Опасные испытания переписывания тегов не проводились.

## Независимый контроллер релизов

Реализация T09 начата с [инспектора Git-доказательств](docs/RELEASE_CORE.md): он проверяет версию и аннотированный тег по точному коммиту без изменений в репозитории. **Это не проверка успешной сборки или готовности релиза** — эти функции появятся на следующих этапах.

## Предварительная проверка релиза

Добавлен [Release Preflight](docs/RELEASE_PREFLIGHT.md) с планом проверок `release-checks.json`. По умолчанию он только проверяет конфигурацию, версию и записи CHANGELOG: `python core/release_preflight.py --repo . --version 0.0.8 --plan`. Выполнение сборки и тестов требует явного `--execute` и доверенной конфигурации. Результат этого компонента **не подтверждает публикацию релиза**.

## Доказательный отчёт и удалённые теги

Раздел [T09.03](docs/RELEASE_REPORT.md) описывает проверку полного SHA аннотированного тега на удалённом Git и машинный/человекочитаемый отчёт. По умолчанию проверка локальная и без запуска команд проекта; сеть доступна лишь с `--verify-remote`, тестовые команды — лишь с `--execute-checks`. **PASS подтверждает только фактически запрошенные проверки, а не готовность выпущенного ПО.**

## Проверка завершённого GitHub Actions

В [T09.04](docs/RELEASE_CI.md) добавлена независимая проверка завершённого CI по GitHub REST API с сопоставлением SHA коммита и обязательных jobs. Вызов требует явного `--verify-ci`, доверенного репозитория и ID запуска. Работает без платных AI API; по умолчанию сеть недоступна. Статус `CI_VERIFIED` не означает RELEASED.

## Публикация GitHub Release и свидетельство

В [T09.05](docs/RELEASE_PUBLICATION.md) реализованы независимая проверка metadata опубликованного GitHub Release и воспроизводимое неподписанное свидетельство проверки. Git-тег и CI не равны опубликованному GitHub Release. Режимы `--verify-publication` и `--format certificate` не создают релиз и не подтверждают скачанные файлы. **На момент проверки GitHub Releases TESSERA отсутствовали**; автоматическое создание не предусмотрено.

## Проверка реальных байтов выпуска

В [T09.06](docs/RELEASE_ASSETS.md) реализована потоковая проверка размера и SHA-256 настоящих прикреплённых файлов GitHub Release, доступная **только явно** через `--verify-publication --verify-assets`. Запись файлов не выполняется; проверка подлинности сборки и готовность исполняемого ПО остаются `NOT_VERIFIED`. На момент проверки у TESSERA нет опубликованных GitHub Releases, поэтому живое испытание остаётся открытым.

## Проверка подписанного происхождения файла

В [T09.07](docs/RELEASE_PROVENANCE.md) добавлена независимая проверка GitHub Sigstore/SLSA attestation через **официальный GitHub CLI**. Она требует реальный локальный файл release asset, подтверждённые метаданные публикации, точный SHA исходного коммита и выбранный подписывающий workflow. По умолчанию выключена. **GitHub Release asset пока отсутствует; live-проверка этого способа распространения NOT_VERIFIED. Подписанный Actions Artifact v0.0.21 проверен отдельно в T09.10.**

**Безопасность:** для проверки attestation требуется GitHub CLI версии `2.102.0` и новее. Уязвимые или неизвестные версии приводят к BLOCKED; фактическое подписание ZIP v0.0.21 подтверждено. Подробности — в [RELEASE_PROVENANCE](docs/RELEASE_PROVENANCE.md).

## Реальный пакет каталога и доверенная сборка

[T09.08](docs/TRUSTED_BUILD.md) добавляет детерминированный ZIP исходников Agent Skills, проверяемый `MANIFEST.json` и отдельную возможность подписанной GitHub attestation. Подписывающий workflow запускается **только вручную на аннотированном теге** и не создаёт GitHub Release. Живое подписание v0.0.21 и независимая проверка выполнены. Для других версий требуется отдельная приёмка. [Правила работы с ветками](docs/BRANCHING.md) теперь отдельно закрепляют: одна ветка на цель/PR, а не на каждое промежуточное изменение.
