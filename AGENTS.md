# Правила работы с TESSERA

[**Русский — оригинал**](AGENTS.md) | [English — перевод](AGENTS.en.md)

TESSERA — отдельный публичный каталог Agent Skills. Канонический репозиторий: `Sashido01/TESSERA`.

1. Сначала изучи README, правила проекта и существующие навыки. Не путай проект TESSERA с приложением, которое использует отдельный навык.
2. Каждый навык размещается в `skills/<имя>/SKILL.md`; имя в метаданных должно совпадать с именем каталога. Сохраняй совместимость со спецификацией Agent Skills.
3. Оставляй навыки независимыми: если требуются отдельные интеграции для Harness, Codex или другой среды, храни их отдельно и не обещай автоматическую активацию без проверок.
4. После изменений выполни `python tools/validate_skills.py`, `python tools/check_public_paths.py`, `python tools/check_translations.py`, `python tools/check_repository_version.py`, `python -m unittest discover -s tests -v` и тесты затронутого навыка. Записывай точный результат.
5. **Та же микроверсионность обязательна и для TESSERA, а не только для навыков.** Исторический старт — `0.0.0`, первая обязательная рабочая микроверсия — `0.0.1`. После каждого самостоятельного проверенного изменения увеличивай корневой `VERSION` на PATCH+1 и обновляй обе версии CHANGELOG в том же коммите. По достижении `.99` после завершения задачи и проверок выпускай следующий `.0` релиз. Если задача не закончена — продолжай `.100`, `.101` и далее до реального завершения. Не создавай фиктивных коммитов и не переписывай старую историю. Правила: [VERSIONING.md](docs/VERSIONING.md).
6. Коммиты и описания изменений пиши понятно, конкретно, по-русски. Не заявляй о выполненных тестах, сборках и публикациях без фактических доказательств.
7. Не загружай секреты, закрытые конфигурации, личные данные, абсолютные пути к рабочим каталогам владельца и файлы других проектов. Локальные пути используйте только для работы в своей среде, но никогда не включайте их в публичные README, инструкции, примеры, сообщения коммитов или релизов. В публичных примерах используйте нейтральные плейсхолдеры (`<project-root>`, `<skills-dir>`). Не делай `push --force`, перемещение чужих тегов или уничтожающие операции с Git.
8. После успешного CI для коммита `main` создаётся аннотированный Git-тег `vX.Y.Z` с понятным русским описанием на основе заголовка коммита. Не передвигай существующие теги. Выпуск GitHub Release и изменение настроек удалённого репозитория — отдельные действия; не считай наличие тега опубликованным приложением.
9. Не изменяй старую опубликованную историю версий. При конфликте правил между навыком и действующим проектом сохрани проектные ограничения и обозначь конфликт.
10. Перед завершением сообщи фактические версии, коммиты, тесты, изменения и остающиеся ограничения.
11. **Языковой приоритет:** `README.md`, `AGENTS.md`, `SKILL.md` и другая основная документация создаются на русском языке. Английские переводы размещаются в `*.en.md` и обновляются в том же изменении. Для `SKILL.md` перевод хранится в `references/SKILL.en.md` без frontmatter. Подробности: [docs/I18N.md](docs/I18N.md).
